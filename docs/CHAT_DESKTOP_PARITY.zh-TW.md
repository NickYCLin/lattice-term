# 對話頁與 Codex Desktop 的功能對照

盤點日期：2026-09-07。這份清單用來追蹤實際能力，不代表已完成全部對齊。
「已有」表示原始碼已有實作；安裝版與實際 CLI 的驗收另行記錄。

## 對照來源與邊界

官方的 Codex Desktop 文件目前轉址到 ChatGPT 桌面版文件。
以[功能總覽](https://learn.chatgpt.com/docs/features)、
[瀏覽器](https://learn.chatgpt.com/docs/browser?surface=app)、
[App Server](https://learn.chatgpt.com/docs/app-server)和
[MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)公開介面為基準。
官方說明明確區分內建瀏覽器與 CLI：內建瀏覽器不包含在 Codex CLI 中。
LatticeTerm 的整合必須自己提供瀏覽器執行環境。

桌面核心維持公開、可稽核；雲端工作區、跨裝置協作與託管服務屬於另一層，
不能以本機介面或 CLI 包裝宣稱已提供，也不應假設可沿用 OpenAI 訂閱服務。

## 功能清單

| 功能 | LatticeTerm 現況 | 尚缺的部分 |
| --- | --- | --- |
| 一般對話、不選專案 | 已實作選填資料夾，每個對話使用獨立工作空間 | 安裝版實際回覆驗收 |
| 專案對話 | 已有工作目錄、分組與移動；更換目錄會重建原生工作階段 | 完整專案管理入口 |
| 串流回覆、推理摘要、工具卡片 | 已有，依 CLI 回報顯示 | 更完整的結構化工具結果 |
| 模型與帳號切換 | 已有，保留各 CLI 原生登入邊界；對話設定可選推理深度：Claude 用 `--effort`（low～max），Codex 依模型清單回報的等級、切回預設時送該模型的預設等級，Gemini 沒有這個設定就不顯示 | 把模型能力（圖片輸入、服務層級等）與模式整合成單一選擇器 |
| 圖片與檔案附件 | 已有檔案選擇、拖放與剪貼簿圖片；貼上的圖片可排隊並跨重開保存 | 剪貼簿檔案物件、輸出圖片與產物預覽 |
| 權限詢問 | 已有指令與檔案核准、Codex 選項式提問、額外權限回覆與 MCP 工具逐次核准；Codex 的 MCP elicitation 可填表（字串、數字、是非、單選，後端依伺服器 schema 重新檢查）或以系統瀏覽器開啟 http(s) 網址後繼續 | 巢狀或多選等更複雜的表單仍只能拒絕；Claude、Gemini 的對話模式尚未轉送 elicitation |
| 瀏覽器操作 | Codex 可選擇啟用 Playwright MCP，以獨立可見視窗執行 | 內嵌頁面、頁籤管理、視覺標註、登入工作階段保存與其他 CLI |
| 中止與續接 | 已有停止、本機持久化、CLI 原生續接、訊息排隊及 Codex 執行中立即補充；重開程式後佇列先暫停。任一則訊息可「從這裡分支」成新對話（複製到該則為止的內容，新的原生工作階段只收到訊息文字的參考摘要），對話可封存到清單下方、隨時取消封存 | 在原對話裡直接改寫舊訊息重跑；各 CLI 原生的分叉續接 |
| 對話完成提示 | 設定裡的提示音；不在載入歷史、失敗或手動停止時播放。視窗不在前景時另發系統通知（對話名稱＋回覆開頭，可在設定關閉）：Linux 直接走 D-Bus，點通知會回到該對話；macOS／Windows 用官方通知外掛，點擊由系統把 LatticeTerm 帶到前景 | macOS／Windows 點通知後自動切到該對話 |
| 排程 | 已有本機排程、背景服務與執行紀錄 | 雲端排程屬獨立服務 |
| Git 變更檢視與審查 | 工具執行紀錄可顯示變更摘要；對話標題列的「變更」面板列出工作資料夾所屬 repo 的已暫存／未暫存檔案，可看單檔 diff、暫存或取消暫存、寫訊息 commit，並把某個檔案的 diff 引用到訊息裡問 AI；也可以點 diff 的任一行留言，累積的留言（附檔名、所在 hunk 與該行內容）一次放進訊息。只呼叫使用者自己的 git，不 push、不改歷史 | PR 與 worktree 工作流程 |
| 整合終端機 | 工作階段頁已有終端機；對話標題列可開關終端機面板，在對話的工作資料夾開使用者自己的 shell（Unix 為 `$SHELL -l`，Windows 為系統目錄的 PowerShell），關掉面板或結束程式就結束該 shell，輸出不保存 | 本機環境動作（例如一鍵跑測試、開啟編輯器）|
| Skills | Agent Fleet 可讀取本機技能中繼資料，CLI 自行載入技能；對話輸入框的「Skills」列出這個助理在帳號與專案裡找得到的 skill（只讀名稱與說明），選了就插入訊息：Codex 用它自己的 `$skill` 寫法，其他助理用一句明確要求 | 在對話內停用特定 skill |
| MCP、Apps、Plugins | 可透過 CLI 已配置的工具執行；瀏覽器工具有程序限定配置。對話設定的「MCP 伺服器」列出該 CLI 設定檔裡的伺服器（範圍、傳輸方式、指令或網址、是否啟用），環境變數與標頭只列名稱，看起來像憑證的參數與網址查詢字串一律遮蔽；新增、移除與登入提供各 CLI 自己的指令可複製 | 直接在介面安裝、啟停與逐工具權限管理；即時連線狀態 |
| 網頁搜尋 | 取決於所選 CLI／模型工具；搜尋與擷取網頁的工具卡片下方列出來源連結（Claude 的 Links 清單、Gemini 結果裡的網址、Codex 開啟的頁面），點擊以系統瀏覽器開啟，只接受 http(s) | 在介面事先顯示各 CLI 是否具備搜尋能力 |
| 圖片生成、語音、電腦控制 | 尚無統一實作 | 各自需要模型服務或本機工具，以及獨立驗收 |
| 網站、互動視覺化、文件產物 | 尚無桌面產物管理介面 | 渲染、預覽、匯出、儲存與發布流程 |
| 記憶、自訂指示 | 工作區共用規則與 CLI 原生規則已有；對話設定裡的「指示與記憶」會列出該 CLI 會讀的使用者層與專案層指示檔（依帳號設定檔的設定目錄），唯讀顯示，並可直接編輯專案共用的 AGENTS.md | 使用者層指示檔與 CLI 自動記憶（如 Claude 的 memory 目錄）的編輯 |
| 多 Agent 與長時間任務 | Agent Fleet 可同時運行多個 CLI | 對話內委派、進度彙整與失敗恢復 |
| 雲端與跨裝置續跑 | 未提供 | 需另外設計託管後端、認證、儲存與協作服務 |

## 本次實作的操作方式

- 設定中的主題改為霧墨、霧藍、暮藍、亞麻與清晰；舊偏好轉換為相近的深淺主題。
- 工作階段頂列固定在側欄上方；狀態說明依可用寬度排列，避免中文字被拆行。
- 終端狀態判斷會先移除顏色控制碼並累積分段輸出；看過執行中提示後，
  程式碼或說明中的「請確認」不會直接蓋過執行狀態，真正的授權選單仍可提醒。
- 動態效果提供完整動態、跟隨系統與減少動態；試播呈現選單、訊息與完成回饋。
  完整動態是使用者明確指定的覆寫；跟隨系統仍遵守作業系統的減少動態設定。
- 一般對話不需要選擇專案。執行目錄位於應用程式資料目錄的
  `chat-workspaces/<thread-id>`，不使用使用者家目錄作為隱含專案。
  刪除對話不會順便刪除助理產生的檔案。
- Codex 對話可勾選「允許使用瀏覽器」。使用固定版本的
  `@playwright/mcp@0.0.80`，由本機 Node.js 啟動；Windows 使用 Edge，
  其他桌面平台使用 Chrome。配置只傳給該次 app-server，不寫入使用者設定。
  [Playwright 的隔離模式](https://github.com/microsoft/playwright-mcp#configuration)
  使用獨立瀏覽器狀態，關閉後不保存登入；它不是網站存取的安全沙箱。
- 瀏覽器功能目前限定 Codex。啟用選項本身不代表工具已成功啟動，
  缺少 Node.js、瀏覽器、下載失敗或 CLI 不支援時，仍需依工具錯誤處理。
  第一輪會先確認工具已載入，才送出訊息；操作核准只適用該次請求，不記住永久允許。
- 對話完成音效沿用設定中的「工作與對話完成提示音」。成功完成才播放，
  取消、失敗、重複事件與重新載入的歷史內容不播放。
- 執行中按 Enter 會把訊息排到下一輪，支援 Claude Code、Codex、Gemini 與 Google Antigravity。
  每個對話最多 8 則；可移除或移回輸入框修改，內容與附件路徑保存於本機。
  失敗、中止或重開程式後先暫停，確認內容後按「繼續送出」。有待送內容時
  鎖定模型、帳號、工作目錄與權限，避免排隊期間變更執行對象。
  本機儲存失敗時保留輸入或暫停排隊，不會默默丟棄待送內容。
- Codex 執行中可按「立即補充」，將文字與附件加入目前回合。透過
  `turn/steer` 核對回合 ID，沿用該回合的模型、帳號與權限。
  收到 CLI 確認後才清空輸入框；拒絕或無法確認時保留內容，不自動重送。
  Claude Code、Gemini 與 Antigravity 仍使用下一輪排隊；舊版 Codex 不支援此介面時也可排隊。
- 截圖可在輸入框直接貼上，或按「貼上圖片」。只在貼上動作時讀取圖片，
  一般文字維持原本的貼上行為；找不到圖片或寫入失敗時保留草稿與既有附件。
  每則訊息最多 10 個附件。PNG 保存在該對話的本機工作空間，不隨程式關閉刪除，
  也不會因移除附件卡片而刪除檔案；排隊與歷史訊息可繼續使用同一份圖片。

## 後續驗收原則

每項功能都要有能操作的完整流程、後端／工具能力、失敗回饋及對應驗證。
本機測試、工具 smoke test、CI、發布檔案與安裝版驗收分開記錄；
功能按鈕存在或 protocol mock 通過，都不能當作實際模型已成功完成工作的證明。

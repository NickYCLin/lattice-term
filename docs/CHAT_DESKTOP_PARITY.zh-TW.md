# 對話頁與 Codex Desktop 的功能對照

盤點日期：2026-09-07。這份清單用來追蹤實際能力，不代表已完成全部對齊。
「已有」表示原始碼已有實作；安裝版與實際 CLI 的驗收另行記錄。

## 對照來源與邊界

官方的 Codex Desktop 文件目前轉址到 ChatGPT 桌面版文件。
以[功能總覽](https://learn.chatgpt.com/docs/features)、
[瀏覽器](https://learn.chatgpt.com/docs/browser?surface=app)、
[App Server](https://learn.chatgpt.com/docs/app-server)和
[MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)公開介面為基準。
官方說明明確區分內建瀏覽器與 CLI：內建瀏覽器不包含在 Codex CLI 中。
LatticeTerm 的整合必須自己提供瀏覽器執行環境。

桌面核心維持公開、可稽核；雲端工作區、跨裝置協作與託管服務屬於另一層，
不能以本機介面或 CLI 包裝宣稱已提供，也不應假設可沿用 OpenAI 訂閱服務。

## 本次實作的操作方式

- 設定中的主題改為霧墨、白瓷、暮藍、亞麻與清晰；舊偏好轉換為相近的深淺主題。
- 工作階段頂列固定在側欄上方；狀態說明依可用寬度排列，避免中文字被拆行。
- 終端狀態判斷會先移除顏色控制碼並累積分段輸出；看過執行中提示後，
  程式碼或說明中的「請確認」不會直接蓋過執行狀態，真正的授權選單仍可提醒。
- 動態效果提供完整動態、跟隨系統與減少動態；試播呈現選單、訊息與完成回饋。
  完整動態是使用者明確指定的覆寫；跟隨系統仍遵守作業系統的減少動態設定。
- 一般對話不需要選擇專案。執行目錄位於應用程式資料目錄的
  `chat-workspaces/<thread-id>`，不使用使用者家目錄作為隱含專案。
  刪除對話不會順便刪除助理產生的檔案。
- Codex 對話可勾選「允許使用瀏覽器」。使用固定版本的
  `@playwright/mcp@0.0.80`，由本機 Node.js 啟動；Windows 使用 Edge，
  其他桌面平台使用 Chrome。配置只傳給該次 app-server，不寫入使用者設定。
  [Playwright 的隔離模式](https://github.com/microsoft/playwright-mcp#configuration)
  使用獨立瀏覽器狀態，關閉後不保存登入；它不是網站存取的安全沙箱。
- 瀏覽器功能目前限定 Codex。啟用選項本身不代表工具已成功啟動，
  缺少 Node.js、瀏覽器、下載失敗或 CLI 不支援時，仍需依工具錯誤處理。
  第一輪會先確認工具已載入，才送出訊息；操作核准只適用該次請求，不記住永久允許。
- 對話完成音效沿用設定中的「工作與對話完成提示音」。成功完成才播放，
  取消、失敗、重複事件與重新載入的歷史內容不播放。
- 執行中按 Enter 會把訊息排到下一輪，支援 Claude Code、Codex 與 Gemini。
  每個對話最多 8 則；可移除或移回輸入框修改，內容與附件路徑保存於本機。
  失敗、中止或重開程式後先暫停，確認內容後按「繼續送出」。有待送內容時
  鎖定模型、帳號、工作目錄與權限，避免排隊期間變更執行對象。
  本機儲存失敗時保留輸入或暫停排隊，不會默默丟棄待送內容。
- Codex 執行中可按「立即補充」，將文字與附件加入目前回合。透過
  `turn/steer` 核對回合 ID，沿用該回合的模型、帳號與權限。
  收到 CLI 確認後才清空輸入框；拒絕或無法確認時保留內容，不自動重送。
  Claude Code 與 Gemini 仍使用下一輪排隊；舊版 Codex 不支援此介面時也可排隊。
- 截圖可在輸入框直接貼上，或按「貼上圖片」。只在貼上動作時讀取圖片，
  一般文字維持原本的貼上行為；找不到圖片或寫入失敗時保留草稿與既有附件。
  每則訊息最多 10 個附件。PNG 保存在該對話的本機工作空間，不隨程式關閉刪除，
  也不會因移除附件卡片而刪除檔案；排隊與歷史訊息可繼續使用同一份圖片。

## 後續驗收原則

每項功能都要有能操作的完整流程、後端／工具能力、失敗回饋及對應驗證。
本機測試、工具 smoke test、CI、發布檔案與安裝版驗收分開記錄；
功能按鈕存在或 protocol mock 通過，都不能當作實際模型已成功完成工作的證明。

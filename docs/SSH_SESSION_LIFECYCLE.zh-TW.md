# SSH 工作階段關閉通知

`session-N` 是 SSH 工作階段 ID，不是 Agent Fleet 的助理 ID。舊版出現
「已停止連線：closed」時，只能知道讀取迴圈結束，無法由這個字判斷是
主機正常關閉 shell、網路中斷，還是閒置連線被設備清掉。

## 關閉與保活

- EOF 只表示主機不再傳送輸出，仍繼續等退出碼與通道關閉，不提早丟掉
  後續的 exit status。收到退出碼 0 顯示「工作階段已結束」，不是中斷警告。
- 非零退出碼、訊號、輸入或調整終端尺寸失敗仍顯示警告，不當成正常結束。
- SSH 每 30 秒送一次協定保活，連續未回覆超過 3 次由 russh 判定失聯。
  保留既有一小時 inactivity timeout 與主機金鑰驗證；保活不是繞過
  防火牆、伺服器閒置政策或帳號限制。
- 已收到的傳輸錯誤或伺服器斷線訊息會保留在通知中；若關閉事件早於
  詳細原因，明確標示缺少退出碼，不再只顯示 `closed`。
- 先註冊關閉事件再連線。啟動回覆抵達前已關閉的連線不會重新加回
  工作階段清單，通知也會補上連線名稱而不是只留下 `session-N`。

這些修正不會自動重連、不重送終端指令，也不恢復已結束的遠端程序。
舊版 `closed` 沒有保存足夠的原因，不能回溯宣稱一定是防火牆造成。

## 驗證界線

回歸測試涵蓋 EOF 與退出碼順序、保活設定、傳輸錯誤保留、啟動競態及
使用者主動關閉。實際主機、防火牆與安裝版的長時間連線仍須分開驗收；
測試或推送成功不代表目前正在使用的 SSH 連線已套用修正。

# Lattice Remote 命令介面

Windows 分享主機提供 cmd／PowerShell；Linux／macOS 分享主機提供
固定的 `/bin/sh`（MCP 的 `shell: "posix"`）。畫面與純終端連線皆可
使用獨立命令通道，兩端都必須更新，並由主機明確授權。

## 使用方式

1. 分享主機開啟 LatticeTerm 後自動待命。在「連線與權限設定」勾選
   「允許獨立命令執行（Windows 或 POSIX）」，再儲存設定。這項授權與鍵盤滑鼠、分享資料夾各自獨立，預設關閉。
2. 觀看端連線後，按遠端畫面工具列的「命令」，選擇主機宣告的 shell。
3. 輸入指令與選填的絕對工作目錄；留空使用主機使用者資料夾。
   Unix 使用絕對目錄並正規化後執行；Windows 不接受 UNC 或裝置路徑。
4. 按「執行」，查看標準輸出、錯誤輸出及結束代碼；需要時按「停止」。
   非零結束代碼會如實顯示，不會自動重試。

cmd 範例：`whoami && dir`。PowerShell 範例：
`Get-Location; Get-Process | Select-Object -First 5`。

每次執行都是新的程序，`cd`、環境變數與 PowerShell 變數不會延續到
下一次。需要互動式輸入、密碼提示或全螢幕終端的程式，請使用終端
工作階段；命令面板的標準輸入會關閉。

## 權限與執行範圍

- 指令以分享主機目前的主機帳號權限執行，不自動提升管理員權限。
  這是執行任意程式的授權，**不受檔案分享根目錄限制，也不是 OS 沙箱**。
- 指令與輸出沿用既有配對、裝置信任及端對端加密連線，中繼只看見密文。
  舊版主機未宣告命令能力時，觀看端不顯示入口，也不傳送新協定請求。
- 每個連線同時一項、同一分享主機最多兩項執行；單一連線最多 256 次。
  重複的執行 ID 不會再次啟動程序，重新連線後不會自動重播指令。
- 指令最多 16 KiB，單次標準輸出與錯誤輸出合計最多 512 KiB。
  可選 30、60 或 300 秒上限；到達限制會停止該次執行並保留已收到的輸出。
- Windows 啟動器先加入具有 kill-on-close 限制的 Job Object，才接收
  使用者指令。停止、逾時、斷線、停止分享及主程序結束時，會清理所屬
  子程序；已完成的檔案修改或外部服務操作不會因此回復。
- cmd 暫存腳本只放在系統暫存目錄下專用的 `lattice-remote-commands`
  資料夾，執行結束後清除。應用程式不寫入指令歷史或輸出紀錄；最新結果
  只保留在目前連線的記憶體中。主機程序異常終止時留下的腳本，會在下一次
  執行 cmd 指令前清掉：只刪這個資料夾裡、名稱符合且超過 15 分鐘的一般
  檔案，還可能在執行中的腳本不會被動到。

## 驗證

本機測試涵蓋能力宣告、協定大小與格式、獨立授權、重複啟動拒絕、
跨分段中文輸出、結果順序及畫面文字轉義。

Windows CI 執行 `host_commands` 原生測試，以及 `commands_e2e` 的
實際 Agent／TCP 加密連線測試，涵蓋 cmd／PowerShell、中文、stderr、
結束代碼、重複 ID、時間／輸出上限與子程序停止。安裝版 GUI 與另一台
Windows 電腦的實機操作仍須分別驗收，不能以 CI 代替。

## Linux／macOS 命令與首次更新

- headless `lattice-agent` 須由主機管理者在原啟動方式加入
  `--allow-commands`，預設不開啟；`--allow-input` 並不包含命令權限。
  桌面分享則由上述獨立勾選框授權，儲存變更會重新啟動分享。
- `/bin/sh -c` 使用固定執行檔，不載入 login profile；工作目錄透過
  subprocess 的 cwd 傳遞，不拼接成 shell source，stdin 關閉。
  命令本身是明確授權的 shell source，可使用 shell 引號。
- 每次執行建立獨立 process group。停止、逾時、斷線會清理該群組，
  不影響互動式終端；程序刻意以新 session 脫離群組或外部服務接受的
  工作不能宣稱已停止。命令結束不能撤銷已完成的修改。
- 純終端只有主機宣告命令能力時才產生 MCP command target，沒有
  screen、input、upload、download 或 Fleet 權限。清單列出
  `commandShells`；未授權或舊版主機不會因此產生可執行 target。
- 沿用桌面 Remote 操作核准卡（可於設定要求逐次核准）。主機命令授權
  與觀看端核准是兩道邊界；任何一端撤權或重連，原 target 失效。
- 首次更新無法靠舊版不支援的命令通道自我升級。先以已授權的互動式
  終端確認架構、安裝路徑與原啟動機制，透過專案官方建置／套件流程
  更新，保留裝置身份及配對儲存；先備份原執行檔及啟動設定。
  正常停止分享再更新，不強殺其他使用者的工作。
  回滾還原備份執行檔及原啟動設定（不含新授權），正常重新啟動。
  不複製配對碼進命令、版本控制或回報。

# 同一張連線卡片使用直連與跳板

在新增／編輯連線的目標區，選擇「可用跳板主機」。選項來自既有的直連 SSH 設定，
不綁定任何使用者的主機名稱。SSH、SFTP、RDP、VNC 各自保留自己的目標主機、帳號與埠；
卡片顯示支援經跳板標籤，主要連線按鈕旁的選單可選直連或使用者命名的跳板。
同一台電腦的其他協定仍使用既有 machineId 分組，不必再建立指向固定本機埠的卡片。

SQL 沿用資料庫設定中的 SSH 路線，在資料庫卡片與工作台提供直連／經跳板選擇。
這個選擇只用於目前操作，不改寫已存路線或憑證綁定；不同路線的 SQL 工作台分開保存草稿。

## 認證、信任與通道生命週期

- 跳板與目標分開認證，密碼依各自的設定 id 存在原有憑證庫；私鑰留在原路徑，通行碼只供執行使用。
- 首次使用跳板，先直接連線並核對 SSH 指紋；指紋未信任或變更時不會自動接受。
- SSH／SFTP 使用內建 russh 的 direct-tcpip 通道連到目標，再進行目標 SSH 握手及主機金鑰驗證，
  相當於 ProxyJump，不需要系統 ssh 執行檔。
- RDP／VNC／SQL 自動綁定 127.0.0.1 的可用埠，不需要使用者保存轉接埠。
  RDP 憑證確認與儲存的綁定仍使用原目標，SQL TLS 使用原伺服器名稱。
- 工作階段結束或建立失敗時釋放通道；SQL 每次操作結束後關閉轉接。
  最多同時 16 個跳板連線，每條 TCP 轉接最多 32 個連入工作，並限制連線與認證時間。
- 錯誤區分跳板連線／認證／信任問題，以及跳板到目標的連線／轉送問題。
- 目前只支援一層跳板；不能把已設定跳板或已整合保留的舊設定當作另一層跳板。

## 舊通道卡片整合

「整合舊通道卡片」只列出下列候選：同帳號、同協定、名稱在去掉括號或經／via 說明後相同，
其中一筆為 localhost、127.0.0.1 或 ::1，且能唯一對應到非本機目標。
沒有目標、名稱無法明確對應或有多個可能目標時，保持原樣。

使用者需逐筆核對目標、選擇跳板並按確認。整合只更新非機密參照：
目標保留原 id 並新增 jumpProfileId；舊設定新增 retiredTo 指向目標，從一般列表隱藏。
舊設定、舊憑證與外部通道不會刪除，可從同一管理畫面還原到列表。
若目標設定被移除，保留的舊設定也會重新顯示。

## 相容與分享

ConnectionProfile 新增選填 jumpProfileId、retiredTo，舊格式缺少欄位時仍是原本的直連。
匯入／匯出只包含非機密參照；首次匯入產生新本機 id 時，也會重新對應同檔跳板與舊設定參照。
密碼、私鑰內容、通行碼與執行中的認證資料不會出現在連線 JSON。

MCP 連線清單回傳跳板 id／自訂名稱，已整合的舊項目不再重複列出；仍不揭露主機、帳號或機密。
MCP 既有 connect_saved_connection 保持原本直連行為。SQL 清單與共享工作台會包含路線參照，
工作台序列化會排除暫時認證；遠端分享沿用既有授權邊界。

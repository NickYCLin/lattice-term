# 待實作項目

## CLIProxyAPI 模型切換涵蓋代理端完整清單

狀態：大部分完成，待真實代理端與安裝版驗收。2026-09-23 使用者回報。

目前現象：啟動時透過 CLIProxyAPI 選擇 Claude 模型，
進入終端輸入 `/model` 後，看到的仍是 Codex 模型選單。
使用者希望能切換到同一個 CLIProxyAPI 接上的所有模型。

需追查：

- 區分 LatticeTerm 啟動選單、代理端 `/models` 與 Codex CLI 原生 `/model`
  三個不同入口，確認清單與目前選定模型的來源。
- 檢查 Codex CLI 是否提供受支援的自訂模型清單或模型切換方式；
  若無法修改原生選單，在 LatticeTerm 提供明確的代理模型切換入口，
  不假裝終端 `/model` 已被接管。
- 保留使用者選定的代理端點與帳號設定，處理切換模型時的原生對話相容性，
  必須重新啟動或建立新對話時先清楚告知。

驗收：

1. 同一代理提供的 Claude、GPT 及其他模型都能列出並選擇，不借用 Codex 原生清單。
2. 多個代理各自取得自己的清單，切換時不誤送到其他端點。
3. 選定模型後，實際請求及代理端回報能證實使用該模型，不能只驗證 UI 名稱。
4. 清單讀取失敗有明確錯誤及重試入口；不悄悄改用其他模型。
5. 切換模型時保留或明確交接對話內容，執行中不可無提示地中止工作。

本項與「同一代理因多個 Codex 帳號而在啟動選單重複出現」分開追蹤；
修正選單重複不代表原生 `/model` 已能顯示代理的全部模型。

目前進度：

- 驗收 4 的重試入口已補上。啟動專案、加開 CLI 與對話設定三處挑模型時，
  代理清單讀不到會就地顯示原因並附「重新詢問」，不必關掉視窗改去設定頁；
  失敗時仍只留手動輸入，不會自己挑一個模型頂替。
- 原生 `/model` 已改列代理的模型（Codex 0.134.0 以後）。做法與限制見
  [Agent Fleet 架構](AGENT_FLEET_ARCHITECTURE.zh-TW.md) 的 CLIProxyAPI 段落。
- 以本機模擬的 OpenAI 相容代理重現並驗證：修正前 `/model` 只列 Codex
  原生模型；修正後列出代理的全部模型，選 `gemini-3-pro` 後送到代理的
  請求 `model` 欄位確實變成 `gemini-3-pro`（驗收 1、3）。選擇寫進專用
  profile，原生 `config.toml` 的預設模型不變；其餘請求內容與修正前逐欄
  相同。
- 驗收 2：清單依啟動時那組代理的位址與金鑰讀取，每個程序各有一份。
- 驗收 5：沿用 Codex 原生 `/model`，在同一個程序內生效，不需重開
  工作階段；工作進行中切換的行為尚未另外驗證。
- 尚未驗證：真實 CLIProxyAPI 伺服器、實際上游模型的回覆，以及安裝版。

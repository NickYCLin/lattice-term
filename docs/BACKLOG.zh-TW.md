# 待實作項目

## CLIProxyAPI 模型切換涵蓋代理端完整清單

狀態：待實作。2026-09-23 使用者回報，尚未完成真實代理端重現。

目前現象：啟動時透過 CLIProxyAPI 選擇 Claude 模型，
進入終端輸入 `/model` 後，看到的仍是 Codex 模型選單。
使用者希望能切換到同一個 CLIProxyAPI 接上的所有模型。

需追查：

- 區分 LatticeTerm 啟動選單、代理端 `/models` 與 Codex CLI 原生 `/model`
  三個不同入口，確認清單與目前選定模型的來源。
- 檢查 Codex CLI 是否提供受支援的自訂模型清單或模型切換方式；
  若無法修改原生選單，在 LatticeTerm 提供明確的代理模型切換入口，
  不假裝終端 `/model` 已被接管。
- 保留使用者選定的代理端點與帳號設定，處理切換模型時的原生對話相容性，
  必須重新啟動或建立新對話時先清楚告知。

驗收：

1. 同一代理提供的 Claude、GPT 及其他模型都能列出並選擇，不借用 Codex 原生清單。
2. 多個代理各自取得自己的清單，切換時不誤送到其他端點。
3. 選定模型後，實際請求及代理端回報能證實使用該模型，不能只驗證 UI 名稱。
4. 清單讀取失敗有明確錯誤及重試入口；不悄悄改用其他模型。
5. 切換模型時保留或明確交接對話內容，執行中不可無提示地中止工作。

本項與「同一代理因多個 Codex 帳號而在啟動選單重複出現」分開追蹤；
修正選單重複不代表原生 `/model` 已能顯示代理的全部模型。

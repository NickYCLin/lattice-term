# 固定配對密碼

「分享這台裝置 → 裝置 ID 中繼 → 固定配對密碼」可自行設定 6～64 個半形
字元，接受大小寫英文、數字及特殊符號，區分大小寫，不接受空白、控制字元、
全形字元。無須每種類型都有，仍建議混用並避免生日、連號及常見密碼。
六至八位純數字 PIN 也能使用，但長且難猜的密碼較安全。

留白仍會產生 128-bit 隨機長碼。32 位大寫十六進位長碼顯示為八組四碼，
輸入該完整大寫分組格式會移除分隔線；這是保留給長碼的顯示格式。
其他密碼不會移除特殊符號或轉成大寫，包括未分組的 32 位十六進位字串。

## 使用與保存

- 桌面分享端只將密碼透過 stdin 交給 Agent，不寫入連線設定或命令列。
  停止分享或結束應用程式後，固定密碼仍需重新輸入；本次沒有新增主機端自動保存。
- 連線端可沿用「成功配對後儲存」功能，保存在作業系統認證儲存區，並綁定裝置 ID。
  不會將密碼放進 WebView localStorage 或一般連線設定。
- 獨立 Agent（包括無介面主機）可用 `--pair-code-file FILE` 或
  `--pair-code-stdin`，檔案須為一般檔案，Unix 權限只限檔案擁有者。
  一行最多 64 個字元，可帶 LF／CRLF；特殊符號不需 shell 跳脫。
  `--pair-code` 雖仍支援，值會出現在程序參數中，不建議使用。
- `lattice-remote` CLI 使用隱藏提示或 `--pair-code-file`，不接受命令列秘密值。

## 新舊版本

新版分享端使用 v4 密碼握手，連線端也必須支援 v4。訊息協定仍是 v2，
不要用應用程式版號判斷是否可連線。

若遠端主機尚未更新，在連線視窗勾選「舊版配對碼相容模式」，CLI 則加
`--legacy-pairing`。v3 主機可使用原來的隨機長碼（直連／中繼皆可）；v2
八位數主機只能透過這台電腦已信任的裝置 ID，先核對永久金鑰才送出證明。
相容模式不會自動勾選，也不會在新版密碼驗證失敗後重試舊協定。
舊碼即使已儲存，仍須明確選用相容模式。新版分享端不接受舊版連線端的握手。

## 安全設計與邊界

1. 使用 `opaque-ke` 的 OPAQUE 密碼驗證金鑰交換，不自行實作橢圓曲線運算。
   套件為 Ristretto255、TripleDH、SHA-512 與 Argon2；註冊步驟在主機本機
   完成，臨時驗證資料及伺服器設定只供該次握手使用，不傳送密碼或註冊紀錄。
2. OPAQUE 雙向確認後，用 HKDF-SHA256 將該次隨機會話金鑰導出為 Noise
   XXpsk3 的 PSK，並使用獨立 v4 prologue。每次金鑰不同，不把短密碼直接
   雜湊成可重複使用的 Noise PSK。中繼裝置 ID 也納入驗證情境，之後仍核對
   Noise 裝置金鑰，收到加密 Hello 才更新信任紀錄。
3. 在密碼驗證前先保留一次嘗試額度；十分鐘內最多五次未完成／失敗的驗證。
   超時或程序中止也計次，成功只退回自己的額度，不清除其他連線失敗紀錄。
   額度按裝置資料目錄共用，不靠 IP，因此換 IP、CLI 或重新啟動都不會歸零。
4. `pairing-attempts.json` 位於身分檔旁，只存時間與隨機識別值，不存密碼或
   密碼雜湊。跨程序鎖保護讀寫，以同目錄暫存檔原子替換；拒絕連結、junction、
   非一般檔案及外部寫入衝突。讀寫失敗或資料損毀時拒絕配對，不自動清空。
5. 短密碼仍可能被線上猜中。攻擊者也可能耗盡配對額度造成暫時無法連線；
   等候最早一次失敗超過十分鐘後再試，不應由服務管理程式刪除限制檔。
   中繼入口仍需存取控管／防濫用；這不是多因素驗證，也不能防止本機帳號遭入侵。

這個整合有本機回歸測試，尚未經第三方安全稽核，不宣稱絕對安全。
協定與套件說明見 [OPAQUE RFC 9807](https://www.rfc-editor.org/rfc/rfc9807.html)
及 [opaque-ke 官方文件](https://docs.rs/opaque-ke/4.0.1/opaque_ke/)。

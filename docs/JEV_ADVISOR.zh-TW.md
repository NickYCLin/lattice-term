# Jev 工作階段注意事項助手

第一版是桌面活動頁的可選功能。使用者選一個 CLI，先在本機讀取並修改片段，
再明確同意將該段文字送給 TypeSafe AI。結果只作提醒，不修改工作階段狀態、
不送出提示、不代答核准、不重啟程序，也不當成程式驗收。

## 申請 TypeSafe

1. 開啟 [官方控制台](https://console.typesafe.ai/)，使用 Google 或電子郵件登入。
2. 若帳號顯示候補或存取申請，依畫面完成；帳號資格與核准時間由 TypeSafe 決定。
3. 取得資格後，從 dashboard 建立 API key，確認額度與計費條件。
   官方公開文件沒有保證每個帳號都有免費額度。
4. 在 LatticeTerm 的「活動」頁展開「工作階段注意事項 · Jev」說明，
   貼上金鑰並選「啟用本次使用」。這個動作只存入原生後端記憶體，不測試 API。
5. 選擇工作階段，按「讀取本機片段」。確認並刪除敏感內容後勾選同意，
   再按「送出這段內容分析」。這一步才會呼叫付費 API。
6. 不使用時按「關閉並清除金鑰」。下次結束並重開 LatticeTerm 後需重新填入。

金鑰不用交給協作者或貼進聊天，也不需要安裝 Python、Node SDK 或 TypeSafe skill。
官方快速入門：[Playground 與 API key](https://docs.typesafe.ai/introduction/quickstart)。
登入後的實際計費介面與申請資格須由使用者在自己的帳號確認。

## 分類與顯示

| 類別 | 意義 |
| --- | --- |
| 等待回答 | 片段包含目前需要使用者回覆的問題或核准要求 |
| 需要登入 | 目前認證失效或登入失敗 |
| 額度限制 | 目前受用量、餘額或速率限制 |
| 更新／重啟 | 更新要求阻擋進度，或更新器明確要求重新啟動 |
| 執行錯誤 | 其他尚未解決的指令、建置或執行失敗 |
| 未見介入要求 | 片段只有一般進度或資訊提示，不代表完成或成功 |
| 無法判斷 | 證據不足、互相矛盾、低信心或不屬於上述情況 |

分類與證據行各問一次 Choice，放在同一個 API 請求。證據只能從本次片段的
行 ID 選取，介面顯示該行原文，不接受模型自行撰寫原因。兩個答案都必須通過
格式、機率分布與選項檢查；分類與證據的信心及所選機率均至少 0.8 才採用，
否則顯示無法判斷。這個門檻是保守的起始設定，尚未用真實資料校準。

## 資料與費用

- 預設關閉；沒有背景掃描、自動分析、啟動連線測試或自動重試。
- 僅針對使用者選定的本機／本機背景服務 CLI 讀取輸出；不接管遠端 Fleet 權限。
- 預覽最多 40 行、8,000 UTF-8 bytes。常見金鑰、URL、信箱、IP 與路徑
  會嘗試遮蔽，但不是完整去識別化。使用者必須自行檢查；客戶資料、內部名稱
  或其他未辨識的秘密仍可能出現在片段裡。
- 終端輸出可能含重繪、歷史錯誤或截斷文字。AI 判讀只對應送出的快照，
  不覆蓋 hook 回報的 `integration` 或既有的 `heuristic` 狀態。
- 送往固定的 `https://api.typesafe.ai/v1/systemone`，不跟隨重新導向，
  不使用環境 HTTP proxy。API key 只存在本次程序記憶體，不寫 localStorage、
  設定檔、活動紀錄或備份；片段與結果也不寫入活動儲存區。
- 同時最多一筆分析，15 秒逾時，回應最多 32 KiB。關閉／更換設定取消本機等待；
  已經送到服務的請求無法撤回，也可能已計費。
- 固定使用 `jev-1.13.0`；版本不符的回應不採用，升級需重新評估。
- 2026-09-23 查閱的官方價格為每百萬輸入 tokens US$0.042、輸出免費。
  每次費用包含問題與判準的 tokens，不只片段；請以帳號帳單與官方現行價格為準。
- TypeSafe 說明不使用客戶請求訓練，但零資料保留另提供給企業客戶，
  不假設一般帳號具有相同條件。

## 驗證與後續安排

本次實作使用合成資料與模擬回應驗證，不取得金鑰、不呼叫真實 Jev API。
測試覆蓋預覽遮蔽與大小限制、同意後才送出、重複點擊、切換工作階段、
停用後丟棄舊結果、無效／低信心回應及只引用原文。
這些檢查不證明 Jev 對繁體中文終端輸出的準確率。

1. **第一版驗收**：確認預設關閉、逐次預覽、原文引用與可隨時停用。
2. **API 實測，另行安排**：由使用者取得 key 與額度，先用合成案例驗證
   認證、計費、延遲及分類。測試成功前不宣稱已連通或已可用於正式工作。
3. **影子評估**：在明確取得資料使用同意後，整理 200～300 筆去識別化案例，
   區分繁中、英文、混合語言、引用範例、過期錯誤、注入文字與不明狀況。
   以 session／來源分開校準集與保留集，避免相同案例改寫後洩漏答案。
   比較規則基準與 Jev 的各類 precision／recall、誤報、漏報、棄答率、
   p50／p95 延遲與實際 token 費用，不只看整體正確率。
4. **決定是否擴充**：先確認真的減少切換分頁與誤報，再評估自動觸發、
   活動排序、歷史搜尋重排及交接片段挑選。自動操作與權限核准不屬於此功能。

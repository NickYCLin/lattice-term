# 資料庫連線、SQL 工作台與 MCP

LatticeTerm 內建 PostgreSQL、MySQL／MariaDB、SQL Server 與 SQLite 驅動。
**不需要安裝任何 SQL 用戶端或 ODBC driver**，包含 psql、mysql、mariadb、
sqlcmd、bcp、isql；SSH 資料庫通道也不需要系統 ssh 執行檔。

## 支援的資料庫、版本與連線資訊

下表的版本是已跑過隔離測試或目前內建的版本，不是最低版本或完整相容性清單。
其他伺服器版本可能使用相同協定，但尚未逐版驗證。

| 資料庫 | 已驗證版本／目前內建版本 | 預設 TCP 埠 | 必填連線資訊 |
| --- | --- | --- | --- |
| SQL Server | 2022 Developer，含強制加密 | 1433 | 主機、實際 TCP 埠、SQL 登入帳號、密碼、資料庫名稱 |
| PostgreSQL | 17 | 5432 | 主機、TCP 埠、帳號、密碼、資料庫名稱 |
| MySQL | 8.0 | 3306 | 主機、TCP 埠、帳號、密碼、資料庫名稱 |
| MariaDB | 11.4 | 3306 | 主機、TCP 埠、帳號、密碼、資料庫名稱 |
| SQLite | SQLite 3；桌面目前鎖定的內建版本為 3.46.0 | 不適用 | 已存在的本機一般檔案之絕對路徑 |

每筆連線另需填寫顯示名稱。四種伺服器資料庫的 TLS CA 都是選填，位於預設
收合的「進階 TLS 設定」；只接受一張 PEM CA 公用憑證、最多 16 KiB，不接受
私鑰。沒有用戶端憑證／私鑰或雙向 TLS 設定。SQLite 不使用帳密、CA 或通道。

連接埠可依實際服務修改。同一主機的不同執行個體請分開儲存，填各自的 TCP
埠與資料庫名稱。主機欄只填 DNS 名稱或 IP，不接受連線網址，也不解析
`主機\執行個體` 或自動探索 SQL Server named instance。

目前版本的 Linux 隔離驗收涵蓋上述四種伺服器的直連與 SSH 通道；Windows／
macOS 的打包設定已盤點，但本輪未驗證其安裝版與 TLS 握手。詳見
[免外部工具與 SSH 驗收紀錄](qa/2026-11-16-database-tool-free-ssh.zh-TW.md)。

## 使用方式

### 介面語系

資料庫設定、連線卡片、SQL 工作台、查詢結果及其輔助說明會使用目前的
介面語系，尚未翻譯的部分會回退英文。資料表、欄位、查詢內容及資料值保留
原文；驅動錯誤改顯示分類後的安全文案，不回傳伺服器原始錯誤或連線字串。
語系切換不會變更連線設定、資料庫帳號權限或 AI／MCP 授權。

SQL 增刪修仍須經過原有確認流程；翻譯不會略過確認或替使用者開啟權限。

### 新增與開啟連線

「我的連線 → 新增連線」使用同一個設定視窗，先選擇用途：

- **遠端連線**：設定 SSH、SFTP 或遠端桌面。
- **資料庫連線**：直接填寫資料庫端點與帳密，不必建立 SSH 或遠端主機。
  不需要指定所屬主機，也不會自動帶入遠端主機的位址或帳密。

資料庫專用連線直接出現在「我的連線」清單，按「開啟 SQL」即可查詢。
同一遠端可保存多筆資料庫設定；查詢時依資料庫設定的連線路徑建立通道。
「全部／遠端／資料庫」可篩選清單，資料庫分類也會列出已歸到遠端的資料庫。
刪除遠端卡片後保留的資料庫仍可在清單開啟。
「新增連線」是共用新增入口；工具列「SQL 工作台」用來開啟查詢工作區。
資料庫卡片與 SQL 工作區的「連線設定」會開啟獨立的資料庫設定表單。
工作階段與對話頁的 SQL 面板也沿用這個入口。

遠端與資料庫保留各自的帳號、密碼、連接埠及 AI 授權，不會自動複製 SSH
密碼。既有資料庫與遠端的關聯保留，但只作為舊資料的快捷入口，不決定
連線路徑。資料庫設定的「連線路徑」另外選擇本機、SSH 或 Lattice Remote；
從遠端卡片的「相關資料庫」新增時，預設與該遠端顯示在同一張卡片。
「卡片顯示（選填）」可改為獨立卡片，或與其他既有遠端
顯示在同一張卡片。合併後「全部」清單只顯示遠端卡片，並提供「連線遠端」
與「開啟 SQL」兩個獨立操作；同一卡片可保存多筆資料庫。切換「資料庫」
篩選仍可直接找到所有資料庫；搜尋只符合資料庫、或遠端卡片已刪除時，
資料庫會獨立顯示，不會因合併而找不到。改回獨立卡片不會更動端點、帳密
或 AI 授權，也不會開啟或中斷任何工作階段。遠端設定只列出相關資料庫
與開啟、編輯入口，不再內嵌另一份設定表單或 SQL 工作台。
未儲存的設定在取消或切換用途時會受到保護，不會直接丟棄。

資料庫表單底部只有一組操作：「測試連線」、「儲存連線」與
「儲存並開啟 SQL」。測試可直接使用未儲存的設定與輸入的密碼，僅查詢
伺服器版本，不寫入設定、密碼或 AI 權限，也不執行自訂 SQL。
沿用已儲存的密碼時，必須符合相同連線識別碼及端點；端點變更後須重填。
測試沿用路徑驗證、20 秒查詢逾時、並行數與設定版本檢查。

### 選擇連線路線

| 連線路線 | 連線來源與準備事項 | 資料庫主機欄的意義 |
| --- | --- | --- |
| 直連（本機） | 本程式所在電腦直接建立 TCP 連線，不需遠端設定 | 從本機可解析、可連線的資料庫 DNS／IP |
| SSH 通道 | 選擇已儲存的 SSH 閘道，先確認主機指紋並保存 SSH 密碼 | 從 SSH 主機可解析、可連線的資料庫 DNS／IP |
| Lattice Remote 遠端轉送 | 先連上已配對的 Remote 主機，分享端開啟資料庫通道能力 | 從 Remote 主機可解析、可連線的資料庫 DNS／IP |

「卡片顯示」只決定清單分組，實際網路路線由「連線路徑」決定。

- **SSH 通道**：選擇已儲存的 SSH 連線，沿用該連線的帳密及已確認的主機
  指紋。目前資料庫通道從憑證庫載入 SSH 密碼，不沿用終端的私鑰登入設定。
  查詢前建立僅綁定本機 loopback 的隨機連接埠，查詢結束或取消後關閉。
- **Lattice Remote 通道**：先連上已儲存的 Remote 主機，並在主機分享設定開啟
  「允許資料庫通道」。通道沿用配對後的端對端加密工作階段，資料庫帳密
  仍由本機儲存。代理也須更新至支援此能力的版本；依能力公告判斷，不比對版本號。
  CLI 代理可使用 `--allow-database-forwarding` 明確啟用，預設關閉。
- **只有 RDP 的主機**：安裝並連線 Lattice Remote 代理，再選擇該 Remote
  連線作為資料庫通道；RDP 畫面連線本身不提供 TCP 轉送。

使用 SSH 或 Remote 路線時，資料庫位址從該遠端主機解析。例如資料庫就在
遠端本機，可填 `127.0.0.1`；直連路線中的此位址則是本程式所在電腦。
改變通道路徑或閘道需要重填資料庫密碼並重新授權 MCP，避免舊密碼送往另一台主機。
每個 Remote 工作階段最多同時轉送八條連線，佇列、資料區塊及連線等待均有上限；
關閉通道分享須停止並重新啟動分享，既有工作階段會一併終止。

每筆設定可個別編輯或刪除；刪除需再次確認，只移除連線設定與保存的密碼，
不刪資料庫、SQLite 檔案或其他版本的連線。整張主機卡片刪除不會連帶刪除
資料庫設定。儲存成功不代表已連線成功，請使用「測試連線／讀取版本」。

### 登入與檔案限制

- SQL Server 目前只有 SQL 帳號／密碼登入；沒有 Windows 整合驗證、
  Kerberos／NTLM、Azure AD／Microsoft Entra ID、存取權杖或受控識別登入。
  安裝 ODBC driver 不會開啟這些功能。
- PostgreSQL、MySQL、MariaDB 使用帳號／密碼；沒有 OAuth、互動式 SSO 或
  用戶端憑證登入欄位，也不保證涵蓋所有伺服器驗證外掛。
- SQLite 僅接受既有本機一般檔案的絕對路徑，不接受網路路徑、符號連結、
  Windows 重新解析點或替代資料流；沒有 SQLCipher 或加密檔案密碼設定。
  不會自動建立資料庫檔案，亦不能經 SSH／Remote 開啟遠端 SQLite 檔案。

## TLS 行為

進階區塊的「信任伺服器憑證（略過驗證）」預設勾選，保持未填 CA 時可直接
連線。此時介面顯示「未驗證伺服器憑證」；加密與驗證伺服器身分是兩件事。

| 設定 | PostgreSQL | MySQL／MariaDB | SQL Server |
| --- | --- | --- | --- |
| 未填 CA，保留預設信任選項 | Prefer：有 TLS 時加密，否則可不加密 | Preferred：有 TLS 時加密，否則可不加密 | On：支援時加密，接受伺服器強制加密；略過憑證驗證 |
| 填入有效 CA，直連 | 強制 TLS，VerifyFull（驗證 CA 與主機名稱） | 強制 TLS，VerifyIdentity（驗證 CA 與主機名稱） | Required，以 CA 驗證憑證及原始主機名稱 |
| 填入有效 CA，SSH／Remote | 強制 TLS，VerifyCa（驗證憑證鏈） | 強制 TLS，VerifyCa（驗證憑證鏈） | Required，以 CA 驗證憑證及原始主機名稱 |
| 未填 CA，取消信任選項 | 強制 TLS，以驅動信任根驗證 | 強制 TLS，以驅動信任根驗證 | Required，以平台／驅動信任根驗證 |

只要有 CA，就一定啟用驗證，略過驗證的勾選會停用；舊設定的 CA 也會實際
用於連線。無法建立受信任憑證鏈、憑證過期或直接連線的主機名稱不符時，
驗證會失敗。
取消信任且未填 CA 時，直接連線也會驗證主機名稱；經通道的 PostgreSQL／
MySQL／MariaDB 因驅動限制，僅驗證憑證鏈，SQL Server 仍驗證原始主機名稱。
原始主機名稱是資料庫主機欄的值，而不是通道在本機建立的 loopback 位址。

TLS 使用內建 rustls；Windows 的 SQL Server 使用平台 native-tls／SChannel，
自訂 CA 加入該次連線的信任設定，不修改系統信任庫。實作與驗收界線見
[TLS 設定驗收紀錄](qa/2026-11-16-database-tls-settings.zh-TW.md)。

## 安全與權限

- 資料表瀏覽與既有 MCP 資料讀取仍走唯讀介面。SQL 工作台另外提供查詢及
  新增、修改、刪除資料；帳號必須具備對應權限。僅瀏覽時請使用唯讀帳號。
  SQL Server 沒有等價的唯讀交易保證，帳號權限仍由資料庫伺服器管制。
- PostgreSQL、MySQL／MariaDB 會開啟唯讀交易。MySQL／MariaDB 的交易指令
  走直接執行，避免 MySQL 不支援預備敘述而連線失敗。SQLite 以唯讀模式開檔並開啟
  `query_only`、關閉 `trusted_schema`。SQL Server 沒有等價的唯讀交易保證，
  以固定查詢及唯讀帳號限制能力，不能把應用程式限制當作伺服器帳號權限。
- MySQL／MariaDB 的文字結果以 UTF-8 驗證及解碼，包含標記為二進位定序的
  系統中繼資料；無效編碼仍回報錯誤，不會靜默替換字元。
- 密碼透過既有系統憑證庫／加密保管庫保存，不放在資料庫設定 JSON，
  不回傳 MCP。變更引擎、主機、連接埠、帳號、資料庫、CA、信任選項或
  通道路線後，須重新填入密碼並重新授權 MCP；只改顯示名稱或卡片分組不會改變連線端點。
- 刪除或更換端點後，清理失敗的舊憑證會保留待清理紀錄。畫面會提示重試，
  不把尚未完成的清理顯示成已刪除。
- 設定使用 revision 比對、程序鎖與原子替換；損壞、空檔、未知版本及
  外部修改不會被靜默覆蓋。

## 錯誤訊息對照

下列為繁體中文分類摘要；介面依語系顯示完整文案。分類依驅動錯誤型別與
代碼判斷，不讀取或回傳伺服器原始錯誤、密碼或連線字串；無法判別時歸為
「其他」。表單驗證、SSH 信任／登入與 Remote 能力不足等錯誤會另外提示，
不一定屬於這五類。

| 分類代碼 | 畫面訊息摘要 | 可檢查的項目 |
| --- | --- | --- |
| `database.error.connection` | 無法連線，或連線中斷／逾時 | DNS／IP、TCP 埠、防火牆、資料庫服務；通道路線要從閘道主機確認可達性 |
| `database.error.authentication` | 帳號或密碼驗證失敗 | 資料庫登入帳號、已儲存密碼、目前支援的登入方式；資料庫密碼與 SSH 密碼分開管理 |
| `database.error.databaseAccess` | 資料庫不存在或無權存取 | 資料庫名稱、帳號的連線／查詢權限，或 SQLite 檔案路徑與檔案權限 |
| `database.error.tls` | TLS 連線或憑證驗證失敗 | CA 是否正確、有效期限、主機名稱及信任設定 |
| `database.error.other` | 資料庫操作失敗 | 資料庫類型、連線設定與 SQL 內容；若涉及寫入，先確認資料結果再決定是否重試 |

不需要另外安裝 SQL 用戶端或 ODBC driver 來修復這些連線錯誤。

## MCP

### SQL 工作台

儲存並選取資料庫連線後，可在內嵌 SQL 工作台編輯語法，下方會顯示結果表格
或伺服器回報的影響筆數。工作區預設選取第一筆已儲存連線並開啟 SQL，
左側可搜尋及切換連線；「資料表瀏覽」與「連線設定」各有獨立頁面。
編輯尚未儲存的連線設定或尚未同步的 SQL 時，須先儲存、同步或取消編輯，
才可切換連線；切換工作區頁面會保留原來的 SQL 與結果。
每次接受一個 `SELECT`、`INSERT`、`UPDATE` 或
`DELETE`，使用目前引擎的 SQL 方言解析；不接受批次、DDL、交易控制或
`SELECT INTO`。查詢會以文字預覽回傳；無法轉為文字的型別請自行使用 `CAST`。
預覽最多 100 筆、64 欄、每格 512 字及約 256 KiB，不是完整匯出。

「執行增刪修」會先顯示連線與這份 SQL，再由使用者勾選並確認執行。
MCP 或其他視窗修改草稿後，舊的確認會失效；寫入不會自動重送。
一般交易會在成功後提交，但資料庫觸發器、外部副作用及非交易式儲存引擎
仍依伺服器行為。逾時、斷線或提交回覆遺失時，請先查詢資料確認結果，
不要直接重送。網路資料庫使用與資料瀏覽相同的帳密、TLS 設定與所選連線路線。

桌面版可拖曳 SQL 標題列到視窗外，或按「移至獨立視窗」。新視窗只開啟
SQL 工作台，不會重複啟動終端工作階段。草稿、版本、執行狀態及結果共用於
同一個程式內；關閉獨立視窗或按「放回主視窗」會恢復內嵌面板。
未同步的草稿必須先同步，才能關閉視窗；關閉整個程式不會持久保存工作台。
工作階段與對話頁的「SQL 資料庫」可開啟同一個並排面板，切換頁面或收合
時保留草稿與結果，不會把查詢資料自動貼到對話或傳給模型。窄畫面使用較大
的覆蓋面板，避免擠窄終端。結果提供目前預覽的本機篩選、固定表頭與筆數，
點選儲存格可展開閱讀及複製，NULL 與空字串分開顯示。

連線設定分為連線位置、登入資料與 AI 存取；桌面以兩欄並排，較窄畫面改為
單欄。密碼可切換顯示，但不會取回或顯示已儲存的密碼，儲存按鈕固定在底部。

最多保留 16 個工作台，可用「關閉工作台並清除草稿與結果」釋放。
iOS SQLite 維持原有唯讀資料表瀏覽，尚未開放 SQL 工作台執行。

MCP 必須先獲得下述連線簿與個別資料庫讀取授權，再由使用者在工作台勾選
「允許 MCP 讀取此工作台的 SQL 與結果」。要修改 SQL，另勾選草稿編輯權限。
修改 SQL 本身只更新草稿。使用者可在各工作台的「AI 執行 SQL 權限」設定：

- 不允許執行（預設）：依勾選內容讀取工作台或編輯草稿。
- 唯讀查詢：允許 AI 編輯 SQL 並執行 SELECT；增刪修仍會被拒絕。
- 查詢與增刪修：另允許 INSERT、UPDATE、DELETE，不逐次要求人工確認。
  資料庫帳號本身的權限仍有效，不會開放 DDL、批次或交易控制。

AI 查詢執行中也可按「撤回 AI 執行授權」；未同步的本機 SQL 草稿會保留，
不會因撤權而被共享草稿覆蓋。已提交的操作不會因撤權自動復原。

MCP 無法自行開啟或提高這些權限。所有執行都需要資料庫分享及工作台分享；
使用 `workbenchExecute` 並帶入剛讀取的 revision，同一版本只能啟動一次。
完成後 SQL、結果與錯誤會同步出現在面板及獨立視窗。寫入前、交易提交前與
回傳結果前會檢查授權與連線綁定；撤回授權會阻止後續執行，提交前發現撤回
會回復一般交易。資料庫觸發器或非交易式引擎的限制仍適用，不自動重送寫入。
未同步的人工作業不會被遠端更新蓋掉；版本衝突時須重新載入共享草稿再編輯。
連線設定變更後，舊工作台的結果與分享權限會失效。

```json
{"action":{"kind":"workbenches","profileId":"已授權的連線識別碼"}}
{"action":{"kind":"workbench","profileId":"已授權的連線識別碼","workbenchId":"工作台識別碼"}}
{"action":{"kind":"workbenchSql","profileId":"已授權的連線識別碼","workbenchId":"工作台識別碼","revision":3,"sql":"SELECT 1"}}
{"action":{"kind":"workbenchExecute","profileId":"已授權的連線識別碼","workbenchId":"工作台識別碼","revision":4}}
```

### 唯讀資料表瀏覽

必須同時開啟桌面的連線簿分享，以及個別資料庫的「允許 MCP 讀取」。
新增連線預設不授權；介面變更端點時會取消原授權，須重新勾選。
桌面需保持開啟，既有 MCP client 可能需要重連才能取得新工具。

使用 `database` 工具，先送 `{"action":{"kind":"list"}}`，再使用回傳的
`id` 作為 `profileId`：

```json
{"action":{"kind":"version","profileId":"已授權的連線識別碼"}}
{"action":{"kind":"tables","profileId":"已授權的連線識別碼"}}
{"action":{"kind":"columns","profileId":"已授權的連線識別碼","schema":"public","table":"sample"}}
{"action":{"kind":"rows","profileId":"已授權的連線識別碼","schema":"public","table":"sample","limit":50,"offset":0}}
```

只開放一般基礎表，不讀 view、foreign table 或 SQLite virtual／shadow table。
每次最多列出 200 張表、64 欄、100 筆資料，每格預覽 512 字，資料列編碼上限
256 KiB；位移最多 100000，查詢 20 秒逾時，最多 4 筆並行操作。
結果是文字預覽，保留 NULL，並非完整型別或二進位匯出。分頁沒有固定排序
保證，資料變動時可能重複或漏列，不能當作備份。遇到容量裁切時，請依
實際回傳筆數累加 offset，不要直接加上要求的 limit；桌面分頁會自動處理。
查詢期間撤回連線簿分享或修改資料庫設定，結果不會回傳。
資料庫內容一律視為不可信資料，不得當成模型或工具的指令。

## 範圍與驗證

資料庫設定獨立保存於應用程式資料目錄的 `database_profiles.json`，目前不納入
既有連線簿備份／還原；遷移電腦請重新設定帳密與 MCP 授權。
本次不提供自訂驅動、Oracle、MongoDB、Redis、DDL 或 migration。
架構以引擎列舉與驅動層分隔，後續可逐種補上，不宣稱涵蓋所有資料庫及版本。

自動測試涵蓋真實本機 SQLite、唯讀拒寫、識別字跳脫、結果裁切、設定衝突、
損壞檔保留及 MCP 授權撤回。目前四種伺服器資料庫的 Linux 隔離測試涵蓋
TLS、免外部工具的直連／SSH、讀取與 SQL 工作台增刪修；Remote 轉送的正式
能力已實作，但本輪四引擎 Docker 矩陣沒有執行 Remote 路線。
這些結果不代表其他伺服器版本、所有資料型別、各平台安裝版或使用者主機
均已驗證。正式發布前仍需桌面安裝版、窄螢幕、大字體與各主題的實機操作驗收。

## 開發者隔離實庫測試

執行 `npm run build:sidecars` 後，使用 `node scripts/test-databases.mjs` 依序測試
PostgreSQL 17、MySQL 8.0、MariaDB 11.4 與 SQL Server 2022；也可在命令
尾端指定 `postgres`、`mysql`、`mariadb` 或 `sqlServer`。
測試主機需要 Node.js、Rust、Docker 與 OpenSSL（可用 `OPENSSL` 指定執行檔）。
SQL Server 容器使用 Developer 版並接受其授權條款。無 Docker 時會明確回報
跳過，不能當成資料庫測試通過。

資料庫初始化工具與 ssh-keygen 在隔離容器中執行；OpenSSL 只產生測試憑證。
應用程式連線子行程的 PATH 僅含不存在的目錄，會先確認所有 SQL 工具與 ssh
不可用，再驗證直連與 SSH 下的查詢、資料表及欄位探索。另驗證 TLS CA、
錯誤密碼、中文／NULL／長字串、分頁、唯讀拒寫與隔離 SQL 增刪修／交易回復。

資料只使用 loopback 隨機埠、隔離 Docker 網路、tmpfs、臨時金鑰與隨機密碼；
結束後清除本次建立的容器、網路與暫存資料，不連正式主機、不讀既有帳密、
不修改系統信任庫。SQLite 另由一般 Rust 測試驗證。詳細結果見
[TLS 紀錄](qa/2026-11-16-database-tls-settings.zh-TW.md) 與
[免工具／SSH 紀錄](qa/2026-11-16-database-tool-free-ssh.zh-TW.md)。

# 發版前檢查：密碼讀取與顯示狀態

## 問題與修正

- 按下「顯示密碼」還在等待憑證庫回應時，若使用者輸入新密碼或清空
  欄位，原本雖不會覆蓋輸入，卻仍會在舊請求結束後把欄位切成明文。
  讀取失敗也會切成明文，下一次按鈕反而變成「隱藏密碼」。
- 讀取期間變更主機等端點欄位，原本仍可能套用先前端點的密碼。
- 現在由憑證 hook 回報是否真正套用讀取結果，只有成功且仍有效的
  請求能開啟明文。變更端點會撤銷尚未完成的讀取並隱藏密碼；過期
  讀取的錯誤也不再蓋過後續輸入。

## 本機驗證

- 新增 6 項元件互動測試，涵蓋輸入新密碼、清空欄位、變更端點、
  讀取失敗、輸入後舊讀取失敗，以及正常顯示後再隱藏。
- 其中輸入、清空、端點變更及讀取失敗等 4 種情境，修正前均重現
  欄位意外切成明文。
- 憑證 hook、連線編輯互動與畫面測試共 28 項通過。
- npm run typecheck、npm run build 與前端入口大小檢查通過。
- 排除 scripts/ios-config.test.mjs 的擴大 Vitest：262 檔通過、
  1 檔略過，共 1922 項通過、4 項略過。iOS 設定測試沿用既有的
  WSL／Python 環境限制排除，本輪沒有重新驗證，不稱完整測試全綠。

## 驗證邊界

使用模擬憑證回應，沒有讀取真實密碼或修改正式連線設定。未更動憑證
儲存格式、後端權限與 MCP 授權規則，也不取消已送出的憑證庫讀取。
本輪尚未完成安裝版、真實系統憑證庫與 CI 驗收，沒有發版。

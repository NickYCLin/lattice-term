# 工作階段權限提示競態檢查

## 範圍與重現

- 檢查工作階段對話的權限輪詢、允許與拒絕，以及延遲回答的成功和失敗結果。
- 同一次 render 連續回答允許與拒絕，原先會送出兩次後端請求。
- 舊回答等待期間出現下一個權限提示，舊回答成功或已由其他地方回答時，
  原先會清除新提示；舊回答失敗時，也會把錯誤掛到新提示上。
- 回答完成前開始的輪詢若稍後傳回舊提示，原先會讓已回答提示重新出現。
- 前四項回歸案例先在修正前失敗；追加過期輪詢案例後，亦先確認失敗再修正。

## 修正方式

- 使用同步 ref 防止 React 更新 busy 狀態前重複回答。
- 回答結果只更新相同工作階段、相同 requestId 的提示。
- 新提示到達時清除舊錯誤；回答成功後提高輪詢版本，忽略較早的讀取結果。
- 保留現有每秒輪詢、後端權限判斷與失敗後重新回答的操作方式。
- 另檢查切換工作階段的呼叫端；ChatView 以 sessionId 作為元件 key，
  切換會重建元件，沒有把 hook 的跨 session 重用假設列為已證實問題。

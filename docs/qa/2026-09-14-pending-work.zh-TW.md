## 已驗證

- 前端 128 個檔案、892 項通過、2 項略過；包含刪除立即保存、
  工作階段投影、語系參數一致性與過期補充指示不呼叫原生端。
- 型別檢查與 production build 通過；入口 391.34 KiB，低於 500 KiB。
- Remote 的 `chat_protocol::tests` 在 Windows 原生執行 3 項通過，
  包含有界 UTF-8 文字、NUL、必要回合 ID 與變更操作分類。
- Remote `cargo check --locked --features agent` 與兩個 Rust manifest
  的 `cargo fmt --all -- --check` 通過。
- 桌面 `cargo check --locked` 通過；Windows 既有的
  `durable_file::AtomicWriteError::after_replace` 未使用警告仍保留。
- 桌面測試直接啟動遇到 `STATUS_ENTRYPOINT_NOT_FOUND`。使用既有
  Windows SDK 在自有副本加入專案的 Common Controls v6 manifest 後，
  聊天橋接 1 項、MCP 畫面隔離與保留上限 4 項、鍵鼠授權與過期畫面
  5 項全部通過。原始測試產物的 SHA-256 在執行前後一致。這是指定
  範圍的 10 項原生回歸，不是整個桌面 library 測試套件。
- 瀏覽器實際操作桌面與 390px 設定頁，九語選項可選且沒有水平溢出。
- 使用真實 React 元件與合成資料，核對側欄回傳原 session ID、刪除
  確認與清單移除。遠端表單只送一次補充指示，帶原回合 ID，確認後
  才清空草稿；舊主機不顯示補充按鈕，仍保留停止回合。

本機瀏覽器產物放在忽略的 `output/playwright/pending-*`，沒有連線
正式主機，也沒有使用現有聊天、模型帳號或付費請求。

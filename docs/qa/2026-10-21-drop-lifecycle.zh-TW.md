# 發版前檢查：拖放附件與路徑的延遲回應

## 問題與修正

- 附件或路徑拖放還在讀取本機資訊時，欄位已停用或元件已關閉，
  舊結果仍會呼叫選取回呼。現在把讀取綁定欄位生命週期，失效後不再
  選取；即使欄位停用後又恢復，也不會重新接受舊結果。
- 拖放處理失敗時，原本會把晚到的錯誤交給最新回呼，可能顯示在
  已重新啟用的欄位。現在只處理仍有效的拖放錯誤，關閉後也不更新。
- 保留原本逐筆處理規則：停用再啟用不會提早釋放尚在執行的拖放鎖，
  避免遠端批次上傳因欄位忙碌狀態切換而意外重疊。

## 本機驗證

- 新增 10 項回歸測試，其中 6 項先重現失敗再修正，並驗證正常選取、
  有效錯誤提示及拖放互斥仍正常。
- npm run typecheck、npm run build 與前端入口大小檢查通過。
- 排除 scripts/ios-config.test.mjs 的擴大 Vitest：261 檔通過、
  1 檔略過，共 1913 項通過、4 項略過。

## 驗證邊界

本輪只修改前端共用拖放流程，沒有變更後端權限、正式主機或發版設定。
忽略失效結果不代表取消已送出的傳輸或本機讀取，也不會撤銷已執行的
選取回呼。測試使用模擬本機資訊與拖放事件，尚未完成安裝版、原生
跨平台拖放或真實主機驗收。ios-config 仍因先前記錄的環境限制排除，
不將本輪結果稱為完整測試全綠。

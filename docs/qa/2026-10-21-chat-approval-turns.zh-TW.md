# 對話頁權限回答的回合隔離

## 範圍與重現

- 延續工作階段權限提示檢查，這輪檢查獨立對話頁的允許、拒絕與問答回傳。
- 快速連續回答同一提示，原先會送出兩次 agent_chat_respond。後端雖有
  已回答檢查，第二次請求仍可能讓前端顯示錯誤。
- 舊回答尚未完成時開始新回合，若新提示重用 requestId，舊回答成功後
  原先會把新提示也標成已允許。
- 前端原先未提供預設 expectedTurnId，且未先擋下已過期的回合。
- 三項回歸案例先在修正前失敗，確定問題後才改程式。

## 修正

- 每次回答固定使用發起當下的回合，對話頁一併傳入畫面對應的回合。
- 相同對話、回合與 requestId 共用同一個待完成請求，不重複送出；
  不同提示仍可各自回答，不做整頁互斥。
- 回覆只更新原本回合；已回答、已結束或回合不符的提示不再送往後端。
- 請求失敗會清除防重狀態，讓使用者修正內容或重試。
- 保留後端既有的權限檢查，不改成自動允許，也未修改 Rust 程式。

## 驗證

- 新增六項測試：防重送、回合綁定、過期回合、新回合重用 requestId、
  不同提示並行、已回答提示及失敗後重試。
- 相關五個測試檔共 64 項通過。
- 擴大回歸：265 檔通過、1 檔略過；1969 項通過、4 項略過。
  使用兩個 worker，排除先前受 WSL／Python 環境限制的
  scripts/ios-config.test.mjs；本輪未重驗該檔，不宣稱完整套件全綠。
- npm run typecheck、npm run build 與入口大小檢查通過；
  入口 373.22 KiB，限制 500 KiB。

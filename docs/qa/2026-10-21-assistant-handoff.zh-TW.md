# 其他助理的背景收尾檢查

## 檢查結果

- Claude Code、Gemini CLI 與 Antigravity 的對話模式共用單輪程序流程，原本已等程序退出才通知畫面完成，沒有 Codex 那個提早顯示完成的空窗。
- 仍有收尾風險：收到最終結果後，若程序不退出，輸出讀取可能一直等待，程序也持續占用。現在保留 30 秒讓程序收尾，逾時只停止這一輪由 LatticeTerm 建立的程序。
- 原本在等待退出前就從執行中清單移除程序；現在確認退出後才移除，避免同一對話提早啟動下一輪，也讓停止操作仍找得到程序。
- 延遲清理會核對對話及輪次，不會誤停下一輪；尚未收到最終結果的工作不會啟動收尾倒數。
- CLIProxyAPI 直接對話使用 HTTP 請求，不會建立原生 CLI 程序或持有原生對話寫入鎖；取消後遠端仍可能繼續處理，不會假稱遠端已停止。
- 其他僅支援工作階段的工具維持長駐終端語意，不因畫面暫時沒有輸出就自動關閉，也不接管其他應用程式。

## 驗證與限制

回歸涵蓋三種協定的最終結果、程序退出前保留執行中登記、
逾時清理，以及舊輪次清理不得影響新輪次。
測試使用本機測試程序，不啟動真實模型或消耗額度。

- Rust 對話模組：87 項通過，6 項真實模型測試維持略過。
- 前端紀錄同步與續聊相關回歸：4 個檔案、34 項通過，包含四種助理的只讀同步。
- TypeScript 型別檢查與前端正式建置通過。

以上是 LatticeTerm 原始碼與本機回歸檢查，不代表各家工具可同時寫入
同一段原生對話。第三方工具持鎖、長駐終端、CI、正式安裝檔及跨應用程式
實際切換仍須分別驗收。不新增交接按鈕，也不自動重送訊息。

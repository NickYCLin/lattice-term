# 發版前檢查：切換連線時的憑證刪除結果

## 問題與修正

- 連線流程共用的單筆憑證 hook，原本會在刪除成功後直接將狀態設為
  未儲存。如果刪除還沒完成就切換連線或憑證類型，舊操作會修改新
  對象的狀態，甚至讓新對象尚未完成的讀取結果失效。
- 現在另以生命週期序號辨識憑證對象。連線、憑證類型改變或元件
  卸載後，舊刪除操作不再修改畫面，也不影響目前對象的讀取。
- 同一對象刪除成功後仍會使較早的讀取失效，避免舊存在狀態回傳後
  又顯示已儲存；刪除失敗保留狀態並允許重試。

## 本機驗證

- 新增 5 項測試，涵蓋切換連線、切換憑證類型、新對象仍在讀取、
  同一對象刷新與刪除重疊，以及刪除失敗後重試。
- 修正前，切換對象相關的 3 項測試均重現新憑證誤顯示未儲存。
- 單筆憑證、清單、RDP 與遠端連線保管庫互動測試共 22 項通過。
- npm run typecheck、npm run build 與前端入口大小檢查通過。
- 擴大 Vitest 使用 2 個 worker，263 檔通過、1 檔略過，共 1935 項
  通過、4 項略過。排除 scripts/ios-config.test.mjs，沿用既有的
  WSL／Python 環境限制；本輪未重新驗證該檔，不稱完整測試全綠。

## 驗證邊界

測試使用模擬原生回應，沒有讀取或刪除真實憑證。後端仍只執行原本
指定對象的刪除，不會取消已送出的操作；此次修正的是完成後的畫面
狀態更新。未更動儲存格式、後端權限或 MCP 授權，尚未完成安裝版、
真實保管庫與 CI 驗收，沒有發版。

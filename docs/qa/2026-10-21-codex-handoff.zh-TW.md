# Codex 背景釋放回歸

## 修正範圍

- 不新增「交回 Codex」按鈕，也不要求使用者手動交接。
- 完成事件等所屬的 Codex 程序退出後才送到畫面，避免回覆已完成但原生對話仍被占用。
- 等待程序退出時繼續讀取輸出，避免補充指示的收據堵在讀取通道。
- 補充指示失敗或逾時後，若該輪已完成，自動釋放閒置程序；不自動重送訊息。
- 有補充指示尚待確認時，不在同一程序啟動下一輪。
- 只清理 LatticeTerm 自己建立且已完成的程序，不終止其他應用程式或執行中的工作。

## 驗證範圍

Rust 回歸涵蓋完成事件與子程序退出順序、補充指示的收據處理、
收據逾時清理，以及執行中工作不得自動釋放。
前端既有回歸確認讀取外部新增紀錄不會啟動模型或送出訊息。
驗證使用測試子程序，不啟動真實模型，也不使用模型額度。

## 邊界

這不是讓兩個獨立 Codex 程序同時寫入同一段對話，也不會繞過原生寫入鎖。
若 Codex Desktop 或長駐終端仍持有對話，LatticeTerm 不能代替對方釋放。
本次不改動工作階段終端的生命週期，也不自動建立對話分支。
已安裝桌面版的跨應用程式切換、CI 與正式安裝檔仍須分別驗收。

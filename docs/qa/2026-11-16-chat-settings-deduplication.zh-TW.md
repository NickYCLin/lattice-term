# 任務 09：對話設定去除重複項目

## 設定入口

| 頂部移除項目 | 調整後入口與原因 |
| --- | --- |
| 來源、帳號、模型 | 底部模型選單已有同一個 AccountModelField，集中在此調整 |
| 推理深度 | 移到同一個底部模型選單，依 CLI 與選定模型提供選項 |
| 工作資料夾 | 底部資料夾新增選取、清除與拖放；保留完整路徑提示與無資料夾的一般對話 |
| 權限模式 | 底部權限選單已有相同功能與權限說明提示 |
| 權限與帳號通用說明 | 隨重複欄位移除；帳號失效警告移到輸入列，選單關閉仍可見 |

頂部保留瀏覽器、這個對話的 MCP 分享、自訂指示與 MCP 伺服器。
新對話仍自動展開頂部進階設定，但模型選單預設收合；可直接由底部
完成來源、模型、推理深度、權限與資料夾設定，亦可不選資料夾送出。

執行中、有排隊訊息或原有其他鎖定條件成立時，底部設定沿用
settingsLocked。工作階段的 PTY 輸入列未提供 directoryControls，
因此仍是唯讀資料夾顯示。

## 推理深度與帳號

模型選單使用目前帳號 config root 的模型清單，不套用另一帳號的清單。
Codex 送出時亦按本次 profileConfigPath 查詢可用模型，驗證選擇的
推理深度；改回預設會送出該模型的預設等級，避免 CLI 保留上次覆寫。
若查詢失敗且有指定推理深度，顯示送出錯誤，不靜默捨棄選擇；
未指定時仍允許 CLI 自行採用預設。查詢期間若該輪已結束，不再送出。
Claude 沿用既有支援的等級；不支援或直接 API 模式不顯示此選項。

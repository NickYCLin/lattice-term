# 對話差距重新比對與本機編輯器動作（任務 21）

## 本輪範圍

重新閱讀指定的官方功能入口及其轉址後的桌面設定、本機環境、通知、搜尋、
瀏覽器、App Server 與 MCP 說明，再對照目前程式和前面任務的驗收紀錄。
[功能對照表](../CHAT_DESKTOP_PARITY.zh-TW.md) 已更新現況、來源邊界、剩餘缺項與難度。
本輪選擇一項低至中難度、不需付費服務的功能：從對話開啟本機 VS Code。

主要剩餘項目包括其他工具專屬呈現、完整模型／能力／模式選擇、單一對話
skill 停用、MCP 設定管理、搜尋能力預檢、活動歷史與動作、專案測試／建置
動作與初始化，以及跨 CLI 原生能力的一致性。雲端與託管服務另列高難度。

## 補上的功能

- 獨立對話標題列與工作階段對話的動作列都有「在 VS Code 開啟」。
- 明確點擊才發出 IPC，不隨載入頁面或切換資料夾自動啟動；同一輪重複點擊只送一次。
- 後端只接受存在的絕對資料夾，canonicalize 後以獨立參數傳入編輯器，使用 `--`
  隔開選項與路徑，不拼接 shell 字串。資料夾空白、引號、&、$ 不會變成指令。
- Unix 優先使用 PATH 的 code；macOS 另辨識標準 Applications 下的 VS Code。
  Windows 使用 Code.exe，支援 PATH、標準使用者及 Program Files 安裝位置，
  不執行 code.cmd。非標準安裝可讓對應可執行檔出現在 PATH。
- 不安裝或下載編輯器，不寫入 CLI／帳號／代理設定，不自動執行測試或工作區指令。
- 找不到編輯器、目錄失效、平台不支援或啟動失敗時顯示對應繁中／英文文案，可重試。
  啟動成功只表示程序請求已送出，不宣稱已看見 GUI 或專案已載入完成。
- 轉換資料夾後不顯示舊請求的晚到結果；開啟狀態不寫入永久偏好。

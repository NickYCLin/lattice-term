# 工作階段閒置後的佇列喚醒

## 修正範圍

- 終端查詢回覆分段抵達時，未收完的控制序列會暫時擋住待送訊息。
  原本收完後不會重新檢查佇列，可能一直等不到下一次狀態變更。
- 官方重複回報相同的閒置或完成狀態時，原本只更新有變化的狀態，
  也跳過佇列檢查。現在每次正式就緒回報都重新檢查派送條件。
- 不放寬官方就緒、使用者草稿、啟動提示、相依工作或執行數限制。
  派送失敗與結果不明的收據仍保留，不自動重試。

## 本機驗證

Windows 使用獨立的測試 PTY、記憶體 writer 與本機 reporter，
不向真實助理送訊息，也不重啟現有工作階段。

- 修正前：4 項回歸測試中，分段回覆及重複就緒兩項失敗，
  未完成草稿與人工送出回合兩項通過。
- 修正後：`queue_wakeup_tests` 共 6 項全部通過，另涵蓋推測就緒、
  執行中、等待確認、啟動阻擋與失敗收據不得自動送出的情境。
- `cargo check`、`cargo fmt --all -- --check` 與新增測試檔的
  `rustfmt --check` 通過。
- Rust library 全套以 4 個測試執行緒重跑：965 項通過、29 項略過。
  首跑的 `codex_mcp_submit_input_profile_diagnostics_preserve_invalidation`
  曾在空 writer 斷言失敗；未修改該測試，單獨重跑及再次全套均通過。
  這次未判定其偶發失敗原因，也未將略過項目當成通過。

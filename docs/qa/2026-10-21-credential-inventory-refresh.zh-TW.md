# 發版前檢查：憑證清單刷新順序

## 問題與修正

- 保管庫畫面載入時，hook 的初始讀取會和畫面的刷新重疊；解鎖或
  切換儲存後端也會觸發刷新。原本較慢的舊回應可能覆蓋最新結果，
  讓已解鎖的清單又顯示不可用。
- 連線清單變更後，先前手動刷新的回應也可能帶回舊連線的憑證項目。
- 初始讀取與手動刷新現在共用讀取序號，只有最新請求能更新清單；
  連線清單變更或元件卸載時，也會撤銷舊請求更新畫面的資格。

## 本機驗證

- 新增 3 項回歸測試，分別涵蓋初始讀取、舊手動刷新，以及連線清單
  切換後的延遲回應。修正前均重現過期結果覆蓋畫面的問題。
- 憑證清單與單筆憑證刷新測試共 5 項通過。
- npm run typecheck、npm run build 與前端入口大小檢查通過。
- 排除 scripts/ios-config.test.mjs 的擴大 Vitest：263 檔通過、
  1 檔略過，共 1925 項通過、4 項略過。iOS 設定測試沿用既有的
  WSL／Python 環境限制排除，本輪未重新驗證，不稱完整測試全綠。

## 驗證邊界

測試使用模擬原生橋接，未讀取真實密碼，也未修改正式連線設定。
此次僅修正清單讀取順序，不更動憑證刪除、儲存格式或 MCP 權限，
也不取消已送往後端的請求。尚未完成安裝版、真實保管庫與 CI 驗收，
沒有發版。

# 發版前檢查：資料庫操作重複送出

## 問題與修正

- 資料庫管理原本只依靠 React 的忙碌狀態阻擋操作。在畫面尚未更新前，
  同一處理函式被連續呼叫，儲存、刪除與查詢都會送出兩次請求。
- 改用同步 ref 鎖保護共用操作入口，初始化載入也使用同一把鎖。
  原本的畫面停用與回應代次檢查保留，請求失敗後仍能重試。

## 本機驗證

- 新增儲存、刪除、查詢共 3 項回歸測試，修正前均重現兩次請求；
  修正後確認只送一次，並驗證失敗提示與重試。
- 資料庫元件與 domain 測試共 11 項通過。
- npm run typecheck、npm run build 與前端入口大小檢查通過。
- 排除 scripts/ios-config.test.mjs 的擴大 Vitest：261 檔通過、
  1 檔略過，共 1916 項通過、4 項略過。該排除沿用既有的 WSL／Python
  環境限制，本輪未重新執行 iOS 設定測試，不稱完整測試全綠。

## 驗證邊界

本輪只調整前端操作互斥，沒有修改資料庫驅動、MCP 授權或後端儲存規則。
回歸測試使用模擬回應，尚未驗收真實資料庫、安裝版或本輪 CI，沒有發版。

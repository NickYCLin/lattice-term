# 發版前檢查：跨協定連線操作互斥

## 檢查範圍

- SSH、SFTP、RDP、VNC 與 Lattice Remote 的連線送出、憑證刪除、
  失敗重試；SSH／SFTP 另檢查主機金鑰信任與重新連線。
- 追查 RDP／VNC session hook，確認既有 race guard 處理啟動期間的
  關閉事件，不會阻止同一表單重複發起兩次連線。
- 檢視 SFTP 上傳批次、卸載保護、目錄讀取順序，以及對話送出與
  同步狀態更新。相關既有互動測試納入回歸，沒有為湊修正數量改寫。

## 重現與修正

- 五種協定的連線表單原本只靠 React busy 狀態停用按鈕。在下一次
  render 前重複送出，仍會呼叫兩次 connect；刪除憑證也能重複送出，
  並與連線同時執行。
- SSH／SFTP 的信任確認在寫入完成前仍能重複點擊，造成兩次寫入
  和兩次重新連線。四種協定先有 10 項測試失敗，加入 Lattice Remote
  後再重現 2 項失敗，均不是只憑 source 推測。
- 改用同步 ref 擋住同一對話框的重入。連線、刪除憑證、信任寫入
  共用同一個操作範圍；SSH 挑選私鑰也納入，避免挑選中送出舊路徑。
- 忙碌期間連關閉與取消一起停用，但刪除憑證不會誤顯示正在連線。
  信任寫入結束後才發起一次連線，失敗則回到可操作的表單。
- connect 發生非預期 rejection 時顯示錯誤並解除忙碌狀態；所有
  操作都在 finally 釋放，避免錯誤後無法重試。

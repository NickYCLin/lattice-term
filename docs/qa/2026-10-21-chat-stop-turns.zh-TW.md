# 對話頁停止操作的回合保護

## 問題與修正

- 對話頁原先只傳對話 ID，未指定回合。停止請求若延後抵達後端，
  可能停到同一對話稍後開始的回合；現在固定傳入發起時的回合 ID，
  使用後端既有的回合比對，不改動 Rust 停止邏輯。
- 呼叫端提供過期回合時，原先仍會先暫停佇列並取消完成通知追蹤，
  才交給後端拒絕；現在先檢查回合，不更動新回合的前端狀態。
- 閒置對話仍可暫停佇列，但不再送出未限定回合的後端停止請求。
  已不存在的對話也不送出請求。
- 遠端工作階段沿用既有取消協定；本次沒有增加遠端回合識別功能。

## 驗證

- 先補測試確認未限定回合、過期停止仍改動狀態、閒置仍送出停止請求
  三種缺口，再修改程式。
- 新增 5 項回歸測試，包含有效回合與不存在對話。使用模擬 Tauri
  bridge，未啟動真實 CLI、操作主機或讀取憑證。
- 擴大回歸：266 檔通過、1 檔略過；1974 項通過、4 項略過。
  使用兩個 worker，另排除先前受 WSL／Python 環境限制的
  scripts/ios-config.test.mjs，本輪未驗證該檔，不宣稱完整套件全綠。
- npm run typecheck、npm run build 與入口大小檢查通過。
  入口 373.22 KiB，限制 500 KiB。

# 對話第一則訊息的派送檢查

## 重現與調整

隔離 PTY 已顯示穩定、空白的提示列，但尚未送出本次工作階段的
第一回合時，桌面 `agent_enqueue` 仍會回傳一筆待送訊息。
Codex 的完成通知要等回合執行後才會產生，因此這筆訊息可能一直
等不到放行事件。恢復歷史對話時，歷史輸出的執行中標記也可能
觸發相同路徑。

修正前，兩項 Rust 重現測試均失敗：已就緒的第一則訊息留在
佇列；未知的啟動畫面則接受入隊，而非保留輸入框草稿。
前端另有兩項測試證明閒置、完成的推測狀態直接擋住送出，
沒有交給後端核對當前畫面。

現在第一則 Codex／Claude 對話訊息由後端沿用前景提示列檢查：
穩定、空白且沒有人工草稿、核准、啟動提示、既有佇列、相依工作
或執行數限制時，才寫入一次。否則回傳未就緒，保留草稿而不入隊。
已開始的回合仍須正式完成通知，安靜畫面不會釋放後續佇列。
既有待送內容與結果不明的派送收據不會自動重試或清除。

回覆，不連接真實帳號。這些結果不代表使用者原本工作階段已恢復，

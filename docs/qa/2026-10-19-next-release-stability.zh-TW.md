# 下一版相容性與穩定性第一批

後續進度見 [2026-10-20 對話與能力驗證](2026-10-20-chat-recovery-and-capabilities.zh-TW.md)。
本文件保留當批結果，不代表後續未完成項目已全部解決。

## 已完成的程式修正

- 復原專案清單只對 Windows 磁碟代號與 UNC 路徑做大小寫與分隔符正規化。
  Unix 路徑保留大小寫及字面反斜線，避免不同專案被當成同一個。
- 模型選擇器補上 Antigravity 解碼；原本能列出選項，但選取時被視為
  未知 CLI 而忽略。四種 CLI 的預設值與含分隔符模型名稱皆有回歸。
- 對話設定的模型選擇器顯示 CLI 模型說明與既有推理等級。圖片、搜尋、
  服務等級目前沒有統一的後端能力欄位，因此明示未提供資訊，
  不從模型名稱推定支援，也不把未知當成不支援。
- 補上主要儲存寫入失敗及復原備份損壞的故障測試，核對原始內容、
  帳號路由、背景執行及 sandbox 欄位不因失敗遺失。

## 本機驗證

- 新增回歸在修正前重現兩項失敗，修正後通過。
- `npm run check`：1759 通過、1 跳過；包含版本、Actions pin、Vitest、
  TypeScript、正式前端建置與入口大小檢查。入口 365.66 KiB，限制 500 KiB。
- 未修改 Rust、原生輸入 guard、iOS harness 或 workflow；未手動派送 CI。
- 儲存故障是隔離 Storage 測試，不是斷電、作業系統重啟或真實磁碟故障驗收。
- 尚未做安裝版 GUI 的模型操作及跨平台實機驗收，不能以本機測試替代。

## 後續仍待完成

1. Windows 新版 Codex 的實際送出、取消、正式 ready 與去重驗收。
   本批不增加版本白名單，既有 raw ESC、草稿、paste 與權限 guard 不變。
2. CLIProxyAPI 原生續聊的安裝版及外部 GUI 平台驗收。
   沿用原 provider、帳號與路由，沒有可信來源時仍拒絕，不猜測 fallback。
3. 具備可核對來源的圖片／搜尋／服務等級能力資訊；本批只有未知狀態提示，
   不宣稱已支援這些能力。
4. Gemini elicitation 與原生同步的非文字內容，須先確認各 CLI 協定與資料來源；
   不把不支援的控制訊息轉成工具批准，也不新增雙向刪除或封存。

以上項目保留驗收界線，不以本批修改宣稱所有下一版工作已完成。

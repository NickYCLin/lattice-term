# 資料庫 SSH 與 Lattice Remote 通道驗收

## 行為

- 資料庫設定可選本機直連、已儲存的 SSH 閘道或 Lattice Remote 連線。
- 卡片分組不再被誤認為通道路徑；資料庫與閘道帳密仍分開保存。
- SSH 使用既有主機指紋及原生憑證讀取流程，僅綁定本機 loopback 的隨機埠。
- Remote 只在主機明確分享資料庫通道後接受請求，沿用已配對的加密工作階段。
  未公告能力的舊代理不會收到新通道訊息，不以版本號決定可用性。
- 通道失敗不回退直連；改變路徑會變更密碼綁定並重設前端 MCP 授權。

## 已執行

- 前端型別檢查、正式建置及入口大小檢查通過。
- 資料庫設定、Remote 分享與設定保存、資料庫模型共 45 項前端測試通過。
- `cargo check` 及兩個 crate 的格式檢查通過。
- 桌面 crate 資料庫、Remote 工作階段、Remote 主機及 SSH tunnel 測試通過。
- Remote crate 完整測試通過；新 TCP 測試另驗證封包界限、舊 Hello 相容性、
  加密資料往返、半關閉、關閉後清理、未授權拒絕及長時間連線的重播記錄界限。
- 隔離 SSH 伺服器測試通過，包含資料往返及停止後釋放 listener。
- 使用既有資料庫憑證，經隔離 SSH 閘道及新編譯的 Lattice Remote 代理，
  分別以 LatticeTerm 的 SQL Server 驅動執行 `SELECT 1` 並確認回覆。
  憑證只透過測試程序環境傳入，不寫入儲存庫或測試輸出。

## 驗收範圍

這次沒有指定實際遠端主機，因此使用本機隔離閘道與代理。測試驗證了完整
通道及資料庫協定，但不代表其他主機的防火牆、SSH forwarding 政策或遠端
代理部署已驗收。只有 RDP 的主機仍須部署並啟用新版 Remote 代理。
本紀錄不等同已發布 GitHub Release 或所有平台安裝包驗收。

Rust 增量編譯快取曾發生編譯器內部錯誤；最終桌面檢查與 SQL 驗收以
`CARGO_INCREMENTAL=0` 重建通過，沒有更改全域工具鏈設定。

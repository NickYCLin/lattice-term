# 工作階段 CLI 權限

## 操作與範圍

- 在工作階段的新專案啟動視窗或新增 CLI 選單選擇權限。
- 支援 Codex、Claude Code、Gemini CLI，依實際啟動的 CLI 組裝參數，包含代理模型路由。
- 預設沿用 CLI 設定，不變更使用者的全域設定。每次重新開啟啟動視窗或切換模型，都回到預設。
- 選擇「全部允許（危險）」才停用新 CLI 的工具權限詢問；畫面會提醒檔案修改、刪除與指令執行風險。
- 不會自動回答現有 CLI 提示，也不會重啟或中斷現有工作階段。現有工作需要另啟動 CLI 才能套用。
- 可修改工作目錄不代表所有指令免詢問。唯讀使用 CLI 的唯讀或規劃模式，不把規劃模式宣稱為作業系統隔離。
- 保留 LatticeTerm 外層隔離設定；「全部允許」不會解除作業系統、管理員政策、專案信任或登入提示。
- 純 CLIProxyAPI 對話不顯示終端權限欄位，仍使用對話頁原有機制。
- 摘要交接使用當次選定的權限。原生對話還原、切換資料夾時保留權限參數，避免還原後又回到不同的批准方式。

## 驗證

- 本機 CLI `--help` 核對三種 CLI 的權限參數與值；Claude Code 使用 `manual`，不是舊版的 `default`。
- 參數映射與原生還原測試涵蓋所有支援模式，以及不支援的 CLI 不加入參數。
- React 互動測試涵蓋預設、全部允許、唯讀，以及純代理不顯示終端權限欄位。
- `npx vitest run src`：233 個檔案、1,614 項測試通過；最後補查切換資料夾、權限映射與互動測試 41 項通過。
- `npm run build`（含 typecheck、正式建置與入口大小檢查）及 `git diff --check` 通過。
- 尚未用安裝版實際執行模型工具呼叫；不同 CLI 版本、企業政策與外層隔離的實際結果仍須實機驗收。

# 資料庫帳密直連與密碼保存驗證

針對 `770830fa fix(database): 改用帳密直接連線資料庫` 重新確認能否實際執行，
並確認 LatticeTerm 能保存資料庫帳密。

## 驗證結果

- Rust 資料庫單元測試：27 項通過，6 項為需容器或真實憑證庫的略過項目。
- `node scripts/test-databases.mjs`（Docker 隔離容器，自簽 CA、隨機帳密）：
  PostgreSQL 17、MySQL 8.0、MariaDB 11.4、SQL Server 2022 各 2 項通過，
  包含未提供 CA 連自簽伺服器、唯讀查詢、拒絕寫入、錯誤密碼與 SQL
  工作台增刪修。SQL Server 容器設定 `forceencryption = 1`，確認驅動不要求
  加密時仍接受伺服器強制加密。結束後容器已全數移除。
- Windows 憑證庫往返（明確執行略過的測試）：經資料庫原生儲存流程寫入
  隨機密碼、讀回比對後刪除，1 項通過；未讀取或變更使用者既有密碼。
- 程式路徑確認：密碼欄留白會沿用已儲存密碼；變更引擎、主機、連接埠、
  帳號、資料庫或通道才需要重填。`hostKey`（顯示在哪張主機卡片）不在
  密碼綁定內，調整卡片歸屬不影響已存密碼。

## 驗證邊界

- 未以使用者實際的 SQL Server 帳密執行 `direct_database_without_ca_reads_one`，
  因為需要使用者自行提供唯讀測試帳密。
- 本機安裝版為 2026.11.6，`770830fa` 尚未包含在任何已發布版本，只在
  2026.11.10 發版 PR（#379，草稿）。安裝版在發布並更新前仍是舊的
  「強制 TLS 並驗證憑證」行為，內網自簽 SQL Server 會連線失敗。

# 發版前檢查：模型清單、帳號狀態與 CLI 更新

## 已重現及修正

### 模型選單沿用舊清單

工作階段及對話頁共用的模型查詢，原本會保留已查詢的設定目錄。
因此重新開啟選單不會重查，同一目錄換帳號也可能沿用前一個帳號的結果。
登入狀態改變時，先前尚未完成的成功或失敗回應還可能覆蓋新清單。

現在每次重新開啟選單或帳號身份改變，都重新取得清單；同輪相同目錄
仍只查一次。已關閉選單或已切換帳號的舊回應不再更新畫面，登出後
也不保留該帳號的清單。不加入寫死的模型名稱，不改 CLIProxyAPI 的來源。

### 更新完成後跳過版本驗證

若背景版本檢查尚未完成，單筆或批次 CLI 更新後的檢查會直接略過。
這會讓進度提早結束，畫面也可能被更新前的回應改回舊版本。

現在更新流程會先等待既有檢查結束，再發出新的版本查詢；新查詢完成前
維持驗證中的進度。不改變原有避免同時執行多個 CLI 更新的限制。

### 帳號狀態被較晚抵達的舊回應覆蓋

手動刷新與輪詢可能重疊。舊查詢較晚完成時，原本可能把已登入狀態
改回未登入，或在刪除帳號、切換設定目錄後恢復舊帳號的狀態。

現在初始讀取、手動刷新及輪詢共用請求序號，只接受最新一次結果。
設定變更先清空舊狀態，設定變更及元件卸載也會讓尚未完成的舊結果失效。

## 驗證邊界

這次沒有修改 Rust。SFTP 附加 SSH 的後端每次建立新 session ID，
本輪未證實「回傳同一 ID 導致重複卡片」的候選問題，因此沒有憑猜測改動。

本機測試及前端建置不代表 CI、正式安裝檔或其他電腦已通過驗收。
正式版本納入本輪提交後，仍須在安裝版確認重新開啟模型選單、切換帳號，
以及單筆和批次 CLI 更新的實際操作。本次檢查不能保證不存在其他問題。

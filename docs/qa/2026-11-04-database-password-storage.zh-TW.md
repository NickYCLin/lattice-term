# 資料庫密碼儲存失敗修正

## 原因與調整

資料庫連線在儲存密碼時產生含冒號的內部識別碼，但共用憑證模組只接受
英數字、連字號與底線。因此即使系統憑證庫可用，資料庫密碼仍會被拒絕儲存。
舊錯誤訊息一律要求解鎖憑證庫，未反映識別碼不相容的情況。

改用 `database-` 加完整 SHA-256，識別碼固定 73 字元，涵蓋連線 ID、引擎、
端點、帳號、資料庫、SQLite 路徑與自訂 CA。保留端點綁定，重新命名或卡片
合併不影響密碼識別；不同連線與端點不會共用密碼。未放寬共用憑證模組的
字元限制，也不把密碼搬到連線設定檔。更新一般儲存錯誤提示，避免一律誤指
為保管庫未解鎖。連線設定 ID 與格式不變。

## 驗證結果

- `cargo fmt --all -- --check` 與 `cargo check --locked` 通過。
- 資料庫測試 23 項通過、3 項略過；略過的 Windows 儲存測試另行明確執行，
  1 項通過。兩項隔離網路資料庫容器測試本次未重跑。
- 憑證相關測試 19 項通過，包含識別碼限制、端點綁定及舊密碼拒絕等回歸。
- Windows 實測使用臨時設定目錄及隨機識別碼、隨機測試密碼，經資料庫原生
  儲存流程寫入系統憑證庫，讀回確認後刪除該筆憑證，並確認已不存在。
  測試設定 JSON 不含密碼；未讀取或變更使用者的既有密碼。
- Windows 無帳號回歸測試新增 `database::` 範圍，預設仍不執行標示忽略的
  真實憑證庫與網路供應者測試。相關 Vitest 腳本測試 5 項通過。
- `git diff --check` 通過；未修改前端元件或網路資料庫驅動。

## 驗證邊界

未操作桌面、連線使用者資料庫或安裝新版。上述結果證明原生儲存流程與
本機 Windows 憑證庫可往返，不代表使用者資料庫的登入、TLS 或查詢已驗收。
目前安裝版必須更新到包含本次修正的版本後，才能使用修正後的儲存流程。

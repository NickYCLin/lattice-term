# 資料庫連線測試回歸

## 修正範圍

資料庫工作區的測試按鈕，在初始設定載入失敗時也要顯示重新載入提示，
不能按下後沒有反應。重新載入保留輸入，測試失敗後仍可重試。

## 測試方式

- 前端涵蓋五種引擎的失敗、解除忙碌與重試，確認不呼叫儲存。
- 原生網路測試使用臨時容器、隨機密碼與臨時 CA，
  驗證 TLS、唯讀查詢、錯誤帳密，以及草稿測試失敗後重試。
- 草稿測試成功不產生設定檔、不改設定版本，也不新增 AI 存取授權。
- 容器內的 SQL 寫入測試只使用隔離樣本，不操作使用者資料庫。

## 本機實測結果

- SQLx 0.9 相容性修正於分支版本 373d3cc6 驗證：
  PostgreSQL 17、MySQL 8.0、MariaDB 11.4、SQL Server 2022
  各通過兩項隔離整合測試，共八項。
- 各引擎涵蓋 CA 與主機名稱驗證、錯誤帳密、草稿重試不儲存、
  唯讀資料表瀏覽，以及 SQL 工作區交易確認、回滾與空結果欄位。
- 同步主線後的 Rust 格式與編譯檢查通過；
  資料庫單元測試 25 項通過、三項預設略過。
  其中兩項網路測試已由隔離容器流程另外執行，
  Windows 憑證庫寫入測試本輪未執行。
- SQLx 0.9 將動態 SQL 改為明確標示的介面；
  中繼資料查詢仍綁定參數，工作區仍先解析單一敘述再執行。
  欄位改由公開的 prepare 介面取得，讀取維持文字協定。
- 主線前端型別檢查、資料庫相關 46 項測試與正式建置通過，
  入口大小為 403.51 KiB，低於 500 KiB 限制。
  本機預設 npm shell 無法找到命令，改以 Node 直接執行
  TypeScript、Vitest、Vite 與入口檢查；型別檢查也以
  npm 指定 PowerShell shell 執行通過，未變更專案腳本。
- 額外完整前端測試為 2232 項通過、四項略過、三項失敗：
  兩項 iOS 腳本測試缺少可用的 bash／python3，
  一項 Windows 安裝鎖計時測試超時；後者單獨重跑兩項全數通過。
  這些結果不當作本機完整測試全綠。
- 測試結束已清除本輪隔離容器，不留測試帳密或修改使用者設定。

## 驗收限制

隔離資料庫通過不代表使用者既有資料庫已完成登入驗收。
TCP 可連通也不代表帳密、TLS 與資料庫名稱正確。
已安裝程式仍須更新到包含憑證清理修正的版本，才能使用原生介面驗收。
不為測試關閉 TLS 驗證、不輸出憑證、不修改使用者連線設定。

# 對話與工作階段共用資料夾識別

## 採用規則

| 路徑類型 | 處理方式 |
| --- | --- |
| 一般 POSIX | 保留大小寫與合法空白；去尾端 `/`、合併中間重複 `/`，保留根目錄 `/`；不將反斜線當 POSIX 分隔符 |
| Windows 磁碟機 | 統一 `/`、不分大小寫；`C:\` 與 `c:/` 同組，磁碟機相對路徑 `C:` 保持不同 |
| Windows verbatim／UNC | 去除 `\\?\` 或 `//?/`；UNC 轉成 `//server/share/...` 後比較，不以伺服器或資料夾簡稱當識別碼 |
| WSL UNC | `wsl$` 與 `wsl.localhost` 統一主機別名，發行版名稱不分大小寫；後面的 Linux 路徑保留大小寫 |
| `~`、符號連結、junction | 後端唯讀查詢既有本機目錄的 canonical 路徑；只有成功結果才用於側欄分組 |
| Linux bind mount | 一般 canonicalize 無法消除掛載別名；讀取 `/proc/self/mountinfo` 推導同檔案系統的候選路徑，再核對裝置與 inode，相同才採用。掛載表讀取失敗時保留一般 canonical 結果 |
| 不存在、無權限、相對路徑或外來系統路徑 | 保留字串正規化結果，不推測實際目錄。UNC／裝置命名空間不做網路探查 |
| 不同父目錄的同名資料夾 | 保持不同群組，顯示能區分的最短父路徑後綴；title 提供完整路徑 |

不直接將 `/home/...` 改成 `/data/...`，也不假定 `/mnt/c/...` 與任意
`C:/...` 一定對應。字串中的 `..` 不會在前端消去，避免跨越符號連結後
誤認成另一個目錄；後端成功解析時才採用真正路徑。

## 本機根因與修正

工作階段頁原本會將 POSIX 路徑也轉小寫，而且 project ID 與比較函式的
尾端斜線規則不同。對話頁則使用另一組規則，甚至有額外的根目錄 ID
特例，因此同資料夾可能分成兩個群組，不同 POSIX 資料夾也可能誤合併。

本機另外存在 projects 子目錄的 bind mount 別名：兩個入口的 canonical
字串不同，但裝置與 inode 相同。只加 std::fs::canonicalize 不足以解決。
新增的後端測試已用目前工作目錄的掛載別名驗證會回到同一個目錄，並以
另一個 inode 的候選目錄測試不能誤合併。

`projectDirectory.ts` 提供共用正規化、project ID 與同名提示；
`useProjectDirectoryIdentity.ts` 分批查詢本機 canonical 結果。兩頁、對話
投影與本機專案目錄清單使用相同字串規則。實際 CLI 工作目錄、帳號、
模型、權限及保存的原始目錄字串不會被 canonical 結果改寫。

## 舊布局與失敗行為

`projectDirectoryLayout.ts` 只轉換資料夾節點及其 parent 參照，保留對話／
工作階段 leaf ID、自訂分類、手動分類與收合狀態。合併位置衝突時優先
保留手動位置，再採已有 canonical 節點的位置及原順序；不能把一個合併
群組同時放在兩個位置，自訂分類本身仍保留。

舊版把不同大小寫的 POSIX 目錄合在一起時，以目前已知的自動隸屬拆開；
對有歧義的手動位置不憑空猜測原意。新後端不可用、目錄不能解析或查詢
失敗時，兩頁都退回共用字串規則。canonical 查詢快取只存在目前畫面的
記憶體中，重新載入會再查詢；側欄布局可以保存合併後的節點 ID，但不
改寫啟動設定，也不拿這份快取繼承其他別名的權限設定。

## 驗證

Vitest 涵蓋斜線、大小寫、磁碟機根目錄、verbatim、UNC、WSL、不應合併
的案例、後端 alias 回覆與失敗回退、舊布局保留，以及兩頁實際元件的
群組與父路徑提示。Rust 涵蓋既有目錄、家目錄、符號連結、掛載表逸出
字元、inode 反例與目前工作目錄的真實掛載別名。

本機測試與建置通過不代表安裝版已更新，也不代表已在 Windows／WSL
實機驗收。未更新安裝版、重啟 CLI 或修改正式資料庫、代理設定。
仍需更新後確認兩頁原本重複的資料夾、群組下的對話、自訂分類位置與
長父路徑的顯示。

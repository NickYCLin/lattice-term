# 發版前檢查：檔案傳輸與遠端目錄競態

## 已重現及修正

- SFTP 傳輸完成並清除後，較晚回來的下載或本機路徑上傳啟動回應，
  會把傳輸列重新加入。現在事件與啟動回應共用更新入口，忽略已清除的
  傳輸 ID，並保留既有完成狀態及不倒退的進度。
- SFTP 初始化快照先包含剛建立的連線，connect 或 attach 回應隨後又
  加入相同 ID，造成重複卡片。兩條路徑現在依 ID 合併。這不是後端
  重用 session ID，也不把不同 ID 的獨立連線合併。
- Lattice Remote 清除傳輸後，較晚抵達的事件、初始化快照或下載啟動
  回應也會恢復傳輸列。現在記住最近 1024 個已清除 ID，忽略這些更新。
  只有後端確認清除成功才移除傳輸，失敗時仍保留原列。
- Lattice Remote 已建立上傳暫存後，若 stream() 或 getReader() 失敗，
  原本不會送出取消。現在取得 reader 也納入錯誤清理，保留原始錯誤，
  並嘗試取消遠端暫存。取消命令失敗仍不代表主機端已完成清理。
- 遠端目錄切換失敗後，畫面原本沿用舊目錄並允許上傳，可能讓使用者
  傳到與輸入路徑不同的位置。現在查詢開始先清空目錄，失敗時停用寫入，
  並保留重新整理與回到上一層的操作。
- 切換遠端連線後，前一連線較慢的目錄回應會覆蓋新連線列表。現在使用
  查詢序號忽略舊結果，連線切換及元件卸載也會讓舊查詢失效。

# 資料庫連線儲存與退出錯誤

## 原因

資料庫密碼識別碼已改為 database- 加 64 位小寫 SHA-256，
但待清理紀錄仍只接受舊的 database: 前綴。修改端點或刪除連線時，
程式會先寫入待清理紀錄，再讀回設定；自己的合法紀錄因此被拒絕，
後續載入、儲存與清理也都失敗。

設定載入失敗時，前端仍允許輸入，但儲存處理會直接返回而沒有提示，
使用者容易以為按鈕沒有反應。未儲存輸入則仍需確認放棄才會退出。

## 修正

- 清理紀錄只接受實際產生的 database- 加 64 位小寫十六進位摘要。
  不放寬共用憑證規則，也不接受任意連線識別碼。
- 保留既有設定、待清理紀錄、版本比對與使用中密碼保護，
  不清空使用者設定檔，不修改連線或將密碼寫入 JSON。
- 初始載入失敗後，可重新載入並保留已輸入的欄位及密碼。
  尚未取得設定版本時，儲存與測試會顯示明確提示。
- 回歸測試涵蓋載入失敗後的取消、關閉按鈕、遮罩與 Escape 退出流程，
  均保留放棄修改確認；也涵蓋儲存失敗後退出、重新載入後儲存。

## 驗證

- TypeScript 檢查通過；相關 Vitest 5 個檔案、63 項測試通過。
- Vite production build 與前端入口大小檢查通過。
- Rust 格式檢查、cargo check --locked 通過。
- 資料庫原生測試 25 項通過；兩項隔離網路資料庫測試及一項
  明確啟用的 Windows 憑證庫測試不在一般測試執行範圍。
- 合成設定測試確認合法清理紀錄可載入、使用中密碼不被清除，
  不合法紀錄仍被拒絕且原檔不變。
- Windows 憑證庫測試另行明確執行，1 項通過；使用臨時設定目錄、
  隨機識別碼與隨機密碼，驗證儲存、讀回、重新載入、刪除連線及
  清理紀錄歸零，最後確認該筆憑證已不存在。測試初始化臨時保管庫，
  不讀取或改動使用者保管庫。

## 驗證邊界

未連線使用者的資料庫、未修改使用者設定或密碼，也未替換已安裝程式。
前端互動使用合成 IPC，不代表安裝版視窗或實際資料庫登入已驗收。
安裝版需要更新到包含本次修正的版本，才會套用新的清理紀錄驗證。

# 發版前檢查：工作階段的遠端檔案傳送

## 問題與修正

- 目標已斷線，較晚回來的目錄檢查仍會開啟確認窗；原本已開啟的
  確認窗也會保留。現在移除失效確認，送出前再次確認連線仍可傳檔。
- 快速重複點擊檢查或確認，原本會送出兩次請求。現在用同步操作鎖
  保護檢查與上傳，確認期間也停用目標、路徑與選檔，維持確認內容一致。
- 舊連線檢查未完成就斷線，現在允許新連線開始檢查；舊結果不能開啟
  確認窗，也不能把新操作解鎖。離開元件後的確認與回應同樣失效。
- 取消請求晚於上傳完成才失敗，原本會把錯誤顯示在下一次傳輸，並重設
  其取消狀態。現在只更新發出取消時的操作，並阻擋重複取消請求。

## 本機驗證

- 新增 7 項互動測試，涵蓋斷線、舊查詢、重複操作、卸載與取消競態。
  最初 4 項先確認失敗，修正後通過。
- npm run typecheck 通過。
- 排除 scripts/ios-config.test.mjs 的擴大 Vitest：259 檔通過、
  1 檔略過，共 1903 項通過、4 項略過。
- npm run build 通過，包含型別檢查、正式前端建置與入口大小檢查。

## 驗證邊界

本輪只修改前端，未改後端權限、正式主機或發版設定。連線失效時
不會把確認改送另一台主機，必須重新檢查並確認目的地。卸載不代表
取消已送出的傳輸。測試使用模擬 API，不能取代安裝版與真實主機驗收。
ios-config 本輪仍因先前記錄的環境限制排除，不能稱為完整測試全綠。

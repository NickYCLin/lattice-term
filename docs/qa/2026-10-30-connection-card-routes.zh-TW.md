# 連線卡片合併與連線選單驗證

## 操作方式

- 卡片只顯示一顆「連線」按鈕；只有一項時直接連線，多項時先選擇。
- 選單顯示各項原名稱、協定、位址與埠號，選取後直接開啟。
- 同協定但不同位址或埠號仍分開列出；不支援的項目保留顯示但不能點選。
- 「合併卡片」可選擇另一張卡片，確認前預覽該卡片內的所有連線。
- 合併沿用既有 machineId 關聯，不刪除連線、不更換 ID 或憑證。
- 每項連線可自行命名，合併保留原名稱，不依主機用途推測通道名稱。
- 之後可從詳細資料拆開；本次未直接合併使用者的任何實際卡片。

## 自動化驗證

- 17 個相關測試檔、156 個測試通過，涵蓋卡片、搜尋、選單、合併、
  資料庫入口、匯出、編輯表單、行動版樣式與翻譯。
- 合併測試確認整張卡片的連線一起保留，名稱、帳號、埠號與 ID 不變，
  重新讀取後仍一致，並可拆開。
- 合併失敗可重試；等待期間禁止重複提交與取消。
- TypeScript 型別檢查、Vite 正式建置及入口大小檢查通過。

## 瀏覽器驗證

使用真正的 ConnectionsView 與合成資料，連線回呼只記錄 ID，沒有連向主機。

- 單項連線直接回傳正確 ID，沒有多餘選單。
- 多項選單保留不同位址的 SSH 連線，選取後回傳正確 ID。
- Shift+Tab 可回到選單末端，Escape 關閉後焦點回到原連線按鈕。
- 合併後兩張卡片成為一張，四項連線仍保留。
- 檢查 390×844 卡片、320×568 與 844×390 選單；頁面及選單無水平溢出，
  列表可捲動，取消按鈕可操作。已檢視窄螢幕截圖。
- 測試流程未新增瀏覽器錯誤；前置 fixture 掛載時的 React 實例設定錯誤
  已排除，不作為產品驗證結果。

## 驗證界線

本次沒有 Rust 變更。瀏覽器 fixture 不代表原生 IPC、實際帳密連線、
安裝版應用程式、實體手機、CI 或正式發版資產已驗收。

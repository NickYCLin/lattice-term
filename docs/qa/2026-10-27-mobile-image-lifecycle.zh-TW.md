# 手機 CLI 圖片上傳生命週期

## 問題與修正

圖片解碼及分段上傳原本沒有隨終端離開而失效。返回清單、隱藏面板或
切換連線後，晚到的回應仍可能送出下一段，失敗時也可能重試。解碼
尚未完成時再次選圖，則會啟動兩個獨立上傳。

- 選圖時同步鎖定，從解碼開始顯示處理狀態，避免重複選圖交錯。
- 上傳綁定目前終端；離開後使本輪失效，所有 await 後重新確認。
  不再追加區塊、重試失敗區塊或更新已離開的畫面。
- 等待先前終端輸入時確認成功狀態。文字輸入未確認、佇列失效或
  停止時，不接著傳圖片，避免圖片路徑接到未完成的操作後面。
- 仍在同一終端時維持既有分段順序、相同 upload ID 及最多一次的
  區塊重試；不改動主機端或 CLIProxyAPI。

已送出的請求無法撤回，平台已開始的解碼也不是強制中止；本次保證的是
離開後不再發起後續區塊或重試。沒有代替主機刪除檔案或新增取消協定。

## 本機驗證

六項新增回歸修正前均失敗、修正後通過，涵蓋：

- 面板隱藏後的成功／失敗回應。
- 返回清單後的成功回應、切換主機後的失敗回應。
- 重複選圖及離開後才完成解碼。
- 先前文字輸入未確認時拒絕圖片。

圖片與輸入相關兩檔共 16 項通過；完整前端 2061 項通過、3 項略過，
TypeScript、正式建置與入口大小檢查通過。本輪沒有修改 Rust。
測試使用隔離的 React／模擬傳輸；真實 iPhone 圖片解碼、網路中斷及
主機檔案結果仍需實機驗收。未發版、未部署、未重啟目前工作階段。

# 遠端 Fleet 重複操作

## 修正

- 啟動儲存項目原本沒有操作鎖，連點會建立不同請求；現在同一主機的
  同一項目在請求完成前只接受一次操作，失敗後允許使用者自行重試。
- 提示送出與取消原本只靠 React busy 狀態停用按鈕，畫面更新前仍可
  重複送出或互相穿插；現在先同步取得操作鎖，再呼叫遠端 API。
- 送出失敗保留提示草稿；成功只清除送出的文字，不覆蓋後續修改。
- 離開主機後再選回來，先前操作的錯誤不能覆蓋新畫面。關閉輸出面板後，
  也不再用晚到的操作結果更新面板。

## 驗證

- 四項新增回歸先重現失敗，再驗證修正，涵蓋連點啟動、過期錯誤、
  提示送出與取消互斥，以及連點取消；另確認失敗後可重試及草稿保留。
- 面板與 Fleet API 相關測試：2 檔、12 項通過。
- `npm run check` 通過：版本一致、Actions 固定版本、完整 Vitest、
  TypeScript、正式前端建置及入口大小檢查。
- 完整 Vitest：272 檔通過、1 檔略過，2043 項通過、2 項略過。

## 邊界

測試使用模擬遠端 API，未建立真實模型工作、取消遠端任務或變更授權。
本批沒有修改 Rust、重啟目前程式、更新本機安裝或發布版本；
安裝版、跨裝置與真實遠端工作流程仍待驗收，預計與下一版一起發布。
